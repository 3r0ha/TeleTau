# answer-check — проверка ответа ученика

Набор `match.json` (v1), функция `matchAnswer` — эталон в `packages/bashkir-text` (`src/match.ts`), раннер — `pnpm vectors`.
Методика — `docs/02-learning-and-gamification.md` §4. Строки синтетические: это сочетания букв, а не слова языка и не учебный контент.

## Вход и выход

```
matchAnswer({ kind: "text" | "tiles", answer: string | string[], accepted: string[] })
  → { verdict: "correct" | "almost" | "typo" | "wrong", matched?: number, hint?: { expected, got, token, index } }
```

- `kind: "text"` — свободный ввод (`free_ru_ba`); `answer` — строка.
- `kind: "tiles"` — плитки (`tiles_ru_ba`); `answer` — тексты плиток в порядке, собранном учеником; перед проверкой они соединяются через пробел.
- `accepted` — все принятые варианты в порядке приоритета; `matched` — индекс совпавшего (нет у `wrong`).
- `expected` сравнивается целиком: лишних полей быть не должно.

## Правила

1. **Слова.** `tokens(s)`: `toComparable(s)` из `bashkir-text` (NFC, двойники, пробелы, нижний регистр) → каждая кодовая точка
   категории Unicode `P*` (пунктуация) заменяется пробелом, кроме `-` (U+002D), `'` (U+0027) и `’` (U+2019), у которых с обеих
   сторон буква (`L*` или `M*`) → разбиение по пробелу, пустые слова отбрасываются. Регистр, пунктуация и лишние пробелы не важны.
2. **correct** — `tokens(answer)` поэлементно равны `tokens(accepted[i])` для какого-нибудь `i`; `matched` — наименьший такой `i`.
3. **almost** — не `correct` ни с одним вариантом, но для некоторого `i` слов столько же и каждое слово совпадает после `fold`
   (свёртка особых букв: ҡ→к, ғ→г, ҙ→з, ҫ→с, һ→х, ә→а, ө→о, ү→у, ң→н и ё→е). `matched` — наименьший такой `i`.
   `hint` — первая (по словам, затем по буквам) кодовая точка, где слово ответа отличается от слова варианта:
   `expected` — буква варианта, `got` — буква ответа (обе строчные), `token` — номер слова, `index` — номер буквы в слове
   (с 0, в кодовых точках формы `toComparable`). Свёртка взаимно однозначна по кодовым точкам, поэтому длины слов совпадают.
4. **typo** — не `correct` и не `almost` ни с одним вариантом, но для некоторого `i` слов столько же, после `fold` различается
   ровно одно слово, расстояние Дамерау — Левенштейна (оптимальное выравнивание строк: вставка, удаление, замена, перестановка
   соседних) между свёрнутыми словами равно 1, а слово варианта не короче 5 кодовых точек («длинное»). `matched` — наименьший такой `i`.
5. Иначе — **wrong**. Пустой ответ и ответ из одной пунктуации — `wrong`.
6. Для `kind: "tiles"` возможны только `correct` и `wrong`: у плиток нет «почти» и опечаток — неверная плитка значит неверный выбор.

Приоритет: сначала `correct` по всем вариантам, затем `almost` по всем, затем `typo` по всем.

Swift и Kotlin пока читают только `bashkir-text/`; порты `matchAnswer` — в M6/M7 (офлайн-проверка), раннеры подключат этот каталог.
