# Личная карточка входа и общий разбор сканера

Решение — ADR 0022 (`docs/adr/0022-self-learners.md`). Эталон — `packages/auth-codes` (`src/login-card.ts`).
Формат той же природы, что карточка места класса (`qr-card/README.md`, ADR 0016): алфавит Crockford, нормализация
ручного ввода, длины частей и контрольная сумма по модулю 1021. Порты Swift и Kotlin проходят эти наборы и объявляют
версии в `SUPPORTED_VERSIONS`.

## Полезная нагрузка

```
TP1.<handle>.<secret>.<check>
```

| Часть | Длина | Смысл |
|---|---|---|
| `TP1` | 3 | префикс `TP` (личная, personal) и версия `1` |
| `handle` | 10 | идентификатор карточки, 50 бит. Не секрет: по нему сервер находит карточку и ограничивает попытки |
| `secret` | 26 | секрет, 130 бит. В базе — SHA-256 (проверка) и шифртекст AES-256-GCM (показ владельцу) |
| `check` | 2 | контрольная сумма с разделителем назначения |

**Контрольная сумма** — та же, что у `TT1`, но по строке `P + handle + secret` (37 цифр base32):

```
r = 0
для каждого символа c из "P" + handle + secret:  r = (r * 32 + value(c)) mod 1021
check = ALPHABET[r div 32] + ALPHABET[r mod 32]
```

Ведущая цифра `P` (значение 22) сдвигает остаток на постоянное ненулевое число, поэтому у одного и того же тела суммы
`TT1` и `TP1` всегда различны: подмена префикса даёт `bad_checksum`, личную карточку не принять за карточку места
класса, а карточку места — за личную. В QR — только полезная нагрузка, без ссылки (как у `TT1`, ADR 0016 §2).

## Общий разбор сканера (`parseLoginCard`)

Сканер «Я ученик → Сканировать карточку» один для обеих карточек. Шаги — как у `parseQrPayload`:

1. Если во входе есть `#`, взять всё после **первого** `#` (ранние карточки места были ссылками `…/q#TT1.…`).
2. Нормализовать (`qr-card/README.md`). Пустая строка — `empty`.
3. Разрезать по `.`. Первый сегмент:
   - `TT1` — вид `seat`, контрольная сумма без разделителя;
   - `TP1` — вид `personal`, контрольная сумма с разделителем `P`;
   - `TT<цифры>` или `TP<цифры>` — `unsupported_version`;
   - иначе — `unknown_prefix`.
4. Сегментов не 4 — `invalid_format`.
5. Символ сегментов 2–4 не из алфавита — `invalid_character` (до проверки длины).
6. Длины не 10 / 26 / 2 — `invalid_format`.
7. Контрольная сумма вида не совпала — `bad_checksum`.
8. Иначе `{ ok: true, kind, handle, secret, payload }`; у карточки места `handle` — это `seat`.

## Наборы

| Файл | Функция | Вход → ожидание |
|---|---|---|
| `login-card/parse.json` (v2) | `parseLoginCard` | строка → `{ ok, kind, handle, secret, payload }` или `{ ok: false, error }` |
| `login-card/build.json` (v2) | `buildPersonalCard` | `{ handle, secret }` → `{ payload }` |
| `login-card/generate.json` (v2) | `personalCardFromRandomBytes` | 36 байт в hex → `{ handle, secret, payload }` |

Контрольные суммы посчитаны независимо от эталона — делением числа в длинной арифметике (BigInt). Свойства (TS,
fast-check, seed 20261105, 2000 прогонов, `packages/auth-codes/test/login-card.test.ts`): сборка и разбор взаимно
обратны; подмена префикса всегда ловится; любая замена одного символа ловится; разбор не бросает исключений.
