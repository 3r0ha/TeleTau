# QR-карточка и код класса — формат для портов

Решение — ADR 0016 (`docs/adr/0016-qr-card-and-class-code.md`). Эталон — `packages/auth-codes` (TS, `pnpm --filter @teletau/auth-codes test`). Порты Swift (M6) и Kotlin (M7) проходят **те же** наборы из `contracts/test-vectors/qr-card/` и `contracts/test-vectors/class-code/` и объявляют поддерживаемые версии (`SUPPORTED_VERSIONS`), как в наборах `bashkir-text`.

Клиентам нужен только **разбор** (сканер и ручной ввод). Генерация и хеширование секретов — на сервере. Векторы генерации нужны, чтобы преобразование «байты → символы» было одинаковым везде.

## Алфавит

Base32 Crockford: `0123456789ABCDEFGHJKMNPQRSTVWXYZ`. Значение символа — его индекс (0–31). Букв `I`, `L`, `O`, `U` в алфавите нет.

Генерация: каждый символ — `byte & 31` очередного криптостойкого случайного байта. 256 делится на 32, поэтому символы распределены равномерно.

## Полезная нагрузка QR-карточки

```
TT1.<seat>.<secret>.<check>
```

| Часть | Длина | Смысл |
|---|---|---|
| `TT1` | 3 | префикс `TT` (ТелеТау) и версия формата `1` |
| `seat` | 10 | идентификатор места (карточки), 50 бит. Не секрет: по нему сервер находит карточку и ограничивает частоту попыток |
| `secret` | 26 | секрет, 130 бит (≥ 128 по ADR 0016). В базе хранится только SHA-256 |
| `check` | 2 | контрольная сумма |

**Контрольная сумма.** Префикс в неё не входит. Строка `seat + secret` (36 цифр base32) читается как число и делится по модулю простого числа 1021. Вычисление без длинной арифметики:

```
r = 0
для каждого символа c из seat + secret:  r = (r * 32 + value(c)) mod 1021
check = ALPHABET[r div 32] + ALPHABET[r mod 32]
```

Она ловит любую замену одного символа и любую перестановку двух соседних разных символов. Случайную ошибку она пропускает с вероятностью 1/1021.

**Ссылка в QR:** `<baseUrl>/q#<payload>`. Завершающий `/` у `baseUrl` не удваивается. Полезная нагрузка стоит во фрагменте после `#`, поэтому браузер не отправляет её на сервер, и она не попадает в журналы веб-сервера и прокси.

## Нормализация ручного ввода

Одна функция для полезной нагрузки и кода класса. Шаги:

1. Удалить символы: U+0009–U+000D, U+0020, U+00A0, U+2007, U+202F (пробелы); U+002D, U+2010–U+2014, U+2212 (дефисы, тире, минус).
2. Перевести ASCII `a–z` в `A–Z`. Другие символы в верхний регистр не переводятся: это не зависит от таблиц Unicode платформы.
3. Заменить похожие символы:
   - `O → 0`, `I → 1`, `L → 1`;
   - кириллические двойники, заглавные и строчные: `А→A`, `В→B`, `С→C`, `Е→E`, `Н→H`, `К→K`, `М→M`, `О→0`, `Р→P`, `Т→T`, `Х→X`, `У→Y`, `З→3`.

Остальные символы сохраняются, и их отвергает проверка алфавита. Это точка, знаки препинания, `U`, прочая кириллица и башкирские буквы. `Ҡ` — отдельная буква, а не двойник `K`, поэтому не заменяется.

## Разбор полезной нагрузки (`parseQrPayload`)

1. Если во входе есть `#`, взять всё после **первого** `#`. Иначе взять вход целиком.
2. Нормализовать. Если получилась пустая строка — `empty`.
3. Разрезать по `.`. Первый сегмент не `TT1`:
   - если он вида `TT<цифры>` — `unsupported_version`;
   - иначе — `unknown_prefix`.
4. Сегментов не 4 — `invalid_format`.
5. Символ сегментов 2–4 не из алфавита — `invalid_character`. Алфавит проверяется **до** длины: после этой проверки все символы — ASCII, и длина одинакова во всех языках.
6. Длины сегментов не 10 / 26 / 2 — `invalid_format`.
7. Контрольная сумма не совпала — `bad_checksum`.
8. Иначе `{ ok: true, seat, secret, payload }`, где `payload` — канонический вид.

## Код класса

6 символов алфавита, 30 бит. Живёт 15 минут. Вход по нему требует одобрения учителя на экране. На экране код показывается как `ABC-DEF`.

Разбор (`parseClassCode`):

1. Нормализовать.
2. Пустая строка — `empty`.
3. Символ не из алфавита — `invalid_character`. Эта проверка важнее неверной длины.
4. Длина не 6 — `invalid_length`.
5. Иначе `{ ok: true, code, display }`.

Контрольной суммы у кода класса нет. Опечатку ловят короткий срок жизни кода, ограничение частоты попыток и одобрение учителем.

## Наборы

| Файл | Функция | Вход → ожидание |
|---|---|---|
| `qr-card/parse.json` (v2) | `parseQrPayload` | строка → `{ ok, seat, secret, payload }` или `{ ok: false, error }` |
| `qr-card/build.json` (v2) | `buildQrCard` | `{ seat, secret, baseUrl }` → `{ payload, link }` |
| `qr-card/generate.json` (v2) | `qrCardFromRandomBytes` | 36 байт в hex (10 — место, 26 — секрет) → `{ seat, secret, payload }` |
| `class-code/parse.json` (v1) | `parseClassCode` | строка → `{ ok, code, display }` или `{ ok: false, error }` |
| `class-code/generate.json` (v1) | `classCodeFromRandomBytes` | 6 байт в hex → `{ code, display }` |

`expected` сравнивается **целиком**, как структура: лишние или недостающие поля — ошибка. Контрольные суммы в векторах посчитаны независимо от эталона: делением 180-битного числа по модулю 1021 в длинной арифметике.

Дополнительные свойства (TS, fast-check, seed 20261103, 2000 прогонов):
- сборка и разбор взаимно обратны, в том числе через ссылку и в нижнем регистре;
- любая замена одного символа и любая перестановка соседних символов дают `bad_checksum`;
- разбор не бросает исключений на произвольной строке;
- нормализация идемпотентна.

Порты повторяют эти свойства своим генератором (SplitMix64 с тем же seed).
