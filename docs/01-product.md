# 01. Продукт: роли, сценарии, функциональный состав

Обозначения приоритетов: **R1** — входит в релиз 1.0 (обязательно), **R2** — релиз 1.x, **R3** — развитие (после 1.x). Мы делаем полноценный продукт, поэтому R1 — это всё, что нужно для реальной эксплуатации в школах республики, а не урезанная демо-версия.

## 1. Роли и права

| Роль | Как появляется | Что может |
|---|---|---|
| Гость | Открыл сайт/бота | Публичный словарь, «фраза дня» без сохранения прогресса, пробный урок |
| Ученик (ребёнок) | Вход по QR-карточке или коду класса | Учиться, участвовать в корпусе (по уровню), лиги, рейтинги класса |
| Ученик-носитель | По результатам входного теста и контрольных заданий (без анкетных вопросов о национальности или родном языке) | Всё, что ученик, + создание переводов, повышенный вес голосов |
| Взрослый ученик | Регистрация по e-mail или телефону с одноразовым кодом, Telegram Login, Сбер ID, Яндекс ID | Самостоятельное обучение, участие в корпусе, «открытые» лиги |
| Родитель | Код привязки от учителя или из приложения ребёнка | Видеть прогресс ребёнка, давать согласие, настраивать лимиты |
| Учитель | Регистрация + подтверждение школой/модератором | Классы, задания, аналитика, «урок-битва», печать QR-карточек, отчёты |
| Администратор школы | Назначается министерством/модератором | Учителя и классы школы, сводная аналитика школы |
| Эксперт | Приглашение Фонда/модератора | Очередь эскалаций, финальные решения, терминология, аудит качества |
| Модератор | Назначается администратором | Жалобы, UGC, ники, блокировки, подтверждение учителей |
| Партнёр API (Фонд, школы, разработчики) | Заявка в портале партнёра | Ключи API, заказы переводов, вебхуки, выгрузки |
| Аналитик министерства | Назначается администратором | Дашборды по республике, районам, школам; выгрузки отчётов |
| Администратор платформы | Технический | Всё, включая настройки, контент-релизы, фичефлаги |

Права реализуются как RBAC + атрибутные политики (ABAC): например, учитель видит только учеников своих классов, аналитик — только агрегаты без детализации до ученика.

## 2. Ключевые сценарии (user journeys)

### 2.1. Учитель подключает класс (R1) — «первые 10 минут»
1. Учитель регистрируется, указывает школу из справочника образовательных организаций РБ → заявка подтверждается (автоматически по домену/списку или модератором).
2. Создаёт класс («5Б, башкирский как государственный») → выбирает программу и учебник, к которым привязаны темы.
3. Печатает PDF с QR-карточками (по одной на ученика, с полем для имени, которое заполняется **от руки** — имя в систему не попадает) и бланком согласия родителей.
4. На уроке дети сканируют QR в приложении или вводят код в браузере → получают псевдонимный ник из безопасного генератора («Шустрая пчёлка 214») → проходят 3-минутный входной тест.
5. Учитель видит класс на дашборде, назначает первую миссию.

### 2.2. Ежедневная миссия ученика (R1) — «Көнлөк кәрәҙ» (дневные соты)
Сессия на 5–10 минут: соты из 7 ячеек, которые заполняются по ходу.
1. **Разминка** — повторение карточек, которые FSRS считает «созревшими».
2. **Новое** — один микро-урок (новые слова и конструкции в контексте).
3. **Фраза дня** — общая для всей республики (как Wordle): перевести одну фразу. После ответа открываются варианты других участников, можно проголосовать за лучший. Результат «созреет» завтра.
4. **Вклад в корпус** — 2–4 микрозадания по уровню: дуэль двух вариантов, «верно/неверно», поиск ошибки, для носителей — перевод.
5. **Итог** — бал (очки-«мёд»), серия, вклад в общий улей класса, карточка «поделиться» без спойлеров (сетка шестиугольников-эмодзи).

### 2.3. Ученик-носитель переводит (R1)
Режим «Хранитель»: лента исходных фраз по приоритету (заказы Фонда, школьная лексика, пробелы в базе) → перевод с панелью башкирских букв → опция «есть другой вариант» → метки (разговорный / литературный / диалект) → вариант уходит на проверку. Носитель видит, как его ячейка «созревает» и «запечатывается».

### 2.4. Эксперт разбирает спорное (R1)
Очередь эскалаций с фильтрами (приоритет, домен, срок) → карточка: исходник, варианты, распределение взвешенных голосов, сводка аргументов от AI, история → действие: принять один или несколько вариантов / отредактировать / отклонить все / предложить свой / вернуть на голосование → обязательный комментарий при отклонении большинства. Решение мгновенно пересчитывает надёжность участников, голосовавших за этот исходник.

### 2.5. Фонд заказывает перевод терминов (R1)
Портал партнёра → «Новый заказ» → загрузка CSV/XLSX со списком терминов и контекстом → приоритет и срок → платформа ставит их в ленты носителей и экспертов → прогресс заказа в реальном времени → выгрузка результата (TSV/XLSX/TMX) и вебхук по готовности. Термины всегда требуют подписи эксперта.

### 2.6. «Урок-битва» в классе (R1)
Учитель запускает битву на интерактивной доске → на экране код и QR → ученики подключаются с телефонов/планшетов → 10 раундов (перевод, аудирование, дуэль) → в реальном времени рейтинг команд (ряды парт) → итог пишется в прогресс. Работает и без телефонов у детей: режим «команды отвечают по очереди», ответы вводит учитель.

### 2.7. Родитель (R1)
Получает код привязки → видит прогресс ребёнка, серию, темы → подписка на еженедельный дайджест (бот/e-mail/пуш) → настройки лимитов экранного времени и тихих часов.

### 2.8. Министерство (R1)
Дашборд: карта районов РБ (охват, активность, прирост корпуса), сравнение школ в пределах лиги, тренды, выгрузка отчёта для госпрограммы (XLSX/PDF). Данные — только агрегаты.

## 4. Нефункциональные требования

| Категория | Требование |
|---|---|
| Производительность | p95 API < 200 мс для учебных запросов; первый экран веба (LCP) < 2,5 с на 4G; холодный старт приложения < 2 с на среднем Android |
| Масштаб | 300 тыс. MAU, 60 тыс. одновременных пиков в учебное время (8:00–15:00), 5 000 участников «урок-битв» одновременно |

| Язык | Корректный рендеринг и ввод всех букв башкирского алфавита на всех платформах, сортировка по башкирскому алфавиту |
| Безопасность и данные | Хранение в РФ, минимизация данных детей, аудит-лог, шифрование; OWASP ASVS L2, MASVS L1 |
