# 09. План работ (роадмап) до релиза 1.0

## 1. Логика плана

- Работа идёт **вехами (M0–M13)**. Каждая веха заканчивается **гейтом жюри** (`10-jury-loop.md`): разработали → проверили агентами-жюри → доделали → перепроверили → и так по кругу, пока гейт не пройден.
- Допущение по ресурсам: ядро команды 6–7 человек + AI-агенты (Claude Code) на написании кода, тестов и ревью. Расчёт команды и бюджета — `12-finance.md`. Если команда меньше, параллельные треки (мобильные, бот) сдвигаются, а критический путь удлиняется примерно на 30–40%.

## 2. Вехи

Для каждой вехи: объём → критерии приёмки → какие жюри проверяют. Общие критерии готовности (Definition of Done) для **любой** вехи — в §3.

### M0. Фундамент
**Объём:** монорепозиторий (pnpm + Turborepo), каркасы `apps/*`, `ios/`, `android/`, `apps/ml-worker`; CI (линтеры, типы, тесты, сборки iOS/Android, проверка контрактов, секрет-сканер); `docker-compose` для локальной среды (Postgres, Valkey, ClickHouse, MinIO); `packages/contracts` с каркасом OpenAPI; пайплайн дизайн-токенов (Style Dictionary → CSS/Swift/Kotlin); каркас тест-векторов с раннерами на трёх языках; ADR 0001–0012; `CLAUDE.md`; соглашения по коду и коммитам.
**Приёмка:** `pnpm dev` поднимает всё одной командой; пустые приложения iOS/Android собираются в CI и показывают экран на токенах; тестовый вектор проходит на TS, Swift и Kotlin.
**Жюри:** архитектура, QA.

### M1. Доступ и организации
**Объём:** модуль `identity` (вход по QR-карточке и коду класса, OAuth для взрослых, refresh-токены с ротацией, устройства), `consent` (версии документов, согласия, отзыв), `org` (импорт справочника школ и районов РБ, классы, членство, учебные годы), регистрация и подтверждение учителя, PDF с QR-карточками и бланком согласия, RBAC/ABAC, аудит-лог; веб: онбординг ученика и учителя, базовые компоненты дизайн-системы.
**Приёмка:** учитель создаёт класс и печатает карточки → ученик входит по QR за < 30 с без ввода ПДн → учитель видит ученика; попытка доступа к чужому классу → 403 (тесты авторизации на каждый эндпоинт).
**Жюри:** безопасность, архитектура, UX, QA.

> **Решение владельца — режим «сначала продукт».** M2 и M3 объединены в одну веху **M2 «Играбельный продукт»**: веб целиком по утверждённому прототипу и каркас Telegram Mini App из M8. План — `docs/plans/M2.md`.
> - **Жюри-агенты** до показа не запускаются, вместо гейта — облегчённая самопроверка (план §5).
> - **Нативные iOS и Android** — после показа.
> - **Не вошедшее из M2 и M3** — в M2b (остаток после показа, до M4) и в вехи, указанные в плане §2.
>
> Разделы M2 и M3 ниже остаются исходным полным объёмом.

### M2. Ядро обучения
**Объём:** `content` + конструктор курса в консоли (юниты, уроки, упражнения, медиа, ревью и релизы контента); все типы упражнений R1 в вебе; пакет `bashkir-text` (нормализация, свёртка, сравнение, сортировка) с тест-векторами; FSRS; Elo-адаптивность; миссия дня; фраза дня с раскрытием; панель башкирских букв; озвучка; офлайн-пакеты контента; стартовый контент 3 юнитов (помечен `needs_native_review`, пока методист не подтвердит).
**Приёмка:** ученик проходит миссию дня целиком; «почти» корректно срабатывает на всех 9 парах букв; FSRS даёт идентичные результаты на векторах; Lighthouse ≥ 90 по производительности и доступности для экранов урока.
**Жюри:** продукт/методика, UX, язык/AI, архитектура, QA.

### M3. Мотивация
> Объединена с M2 «Играбельный продукт» (решение владельца). В показ входят мёд, серия с заморозками, недельная лига и квест класса, остальное — по плану `docs/plans/M2.md` §2.

**Объём:** `progress` (журнал баллов с отложенными начислениями, серии с заморозками и школьным календарём, достижения), лиги медоносов, генератор орнамента (`packages/ornament` + тест-векторы), улей и квест класса, сервис уведомлений (тихие часы, частотные лимиты, шаблоны), сертификаты PDF с QR-проверкой.
**Приёмка:** неделя лиги симулируется в тестах end-to-end (повышение/понижение); одинаковый орнамент по вектору на вебе; уведомления не уходят в тихие часы (тест по часовому поясу Уфы).
**Жюри:** продукт/методика, UX, QA, безопасность (уведомления детям).

### M4. Корпус и Consensus Engine (параллельно с M3)
**Объём:** `corpus` + `consensus` (варианты, голоса как неизменяемые события, модель надёжности, правила решений, маршрутизация, контрольные задания, эскалации, апелляции), консоль эксперта и модератора, антифрод v1, `ml-worker` (Dawid–Skene, Bradley–Terry, симулятор), импорт открытых корпусов с проверкой лицензий, релиз датасета v0 (внутренний).
**Приёмка:** симулятор: точность ACCEPT ≥ 95% при 30% «шумных» участников и 5% сговорщиков; пересчёт всей базы из журнала голосов детерминирован; эксперт разбирает эскалацию с клавиатуры < 30 с.
**Жюри:** язык/AI, архитектура, продукт, безопасность, QA.

### M5. AI-слой на GigaChat
**Объём:** `ai-gateway` (авторизация GigaChat и обновление токена, повторы, предохранитель, бюджеты по функциям и пользователям, кеш, реестр промптов, удаление ПДн), функции: объяснение ошибки, подсказки, генерация русских исходников, сигналы для консенсуса (обратный перевод, семантическая близость), помощь модерации, AI-сводка класса для учителя, сводка спора для эксперта; набор оценок (golden sets) и ночной регресс; маркировка AI-контента.
**Приёмка:** ни один ответ AI, содержащий башкирский текст вне проверенной базы, не показывается ученику без пометки (автотест); стоимость на активного пользователя в пределах бюджета (`04-ai-gigachat.md`); при недоступности GigaChat продукт работает (деградация без ошибок).
**Жюри:** язык/AI, безопасность, архитектура, QA.

### M6–M7. Нативные приложения iOS и Android (параллельно)
**Объём (обе платформы):** онбординг (QR-сканер), главная «Улей», плеер урока со всеми типами упражнений, дуэли, фраза дня, улей класса, профиль с орнаментом, лиги, режим родителя, лёгкий режим учителя (класс, битва), офлайн-пакеты и синхронизация, пуши (провайдеры за интерфейсом), виджеты, хаптика, Rive-маскот, тёмная тема, Dynamic Type/масштаб шрифта, VoiceOver/TalkBack, три возрастных режима; Android — сборки под несколько магазинов.
**Приёмка:** все тест-векторы зелёные на устройстве; миссия дня проходится в авиарежиме и корректно синхронизируется (без дублей баллов); холодный старт < 2 с на эталонном среднем Android; снапшоты экранов в обеих темах и при 200% шрифте без обрезаний.
**Жюри:** UX, архитектура, QA, безопасность (MASVS), продукт.

### M8. Telegram-бот и Telegram Mini App
**Объём:** канально-независимое ядро диалогов + адаптер Telegram (Bot API, вебхуки, очередь исходящих с повторами), привязка аккаунта одноразовым кодом, фраза дня, быстрые дуэли, напоминания, рейтинг класса, команды учителя, дайджест родителя, Telegram Mini App (веб в режиме `/miniapp`, проверка подписи `initData`).
**Приёмка:** сценарии ядра покрыты контрактными тестами; бот не сохраняет данные из профиля Telegram и не отправляет персональные данные в сообщениях (автотест шаблонов); при недоступности Bot API продукт работает без ошибок, а ссылка Mini App открывается в обычном браузере.
**Жюри:** UX, безопасность, QA.

### M9. Соревнование, учитель, министерство
**Объём:** «Индекс улья» (класс/школа/район) с лигами по категориям школ и антинакруткой, сезоны, карта районов, урок-битва (WebSocket, экран доски, режим без телефонов), дашборд учителя (тепловая карта, «кому нужна помощь», задания, отчёты), дашборд министерства (агрегаты из ClickHouse, выгрузки), дашборд Фонда.
**Приёмка:** 500 одновременных участников битвы в нагрузочном тесте с задержкой < 300 мс p95; рейтинг не меняется от накрутки сговором в тестовом сценарии; дашборд министерства не позволяет выйти на уровень ученика.
**Жюри:** продукт, UX, архитектура, безопасность, QA, заказчик.

### M10. Публичный API и данные
**Объём:** `/public/v1`, портал партнёра (заявки, ключи, квоты, документация), заказы переводов и вебхуки, релизы датасета (форматы, манифест, отчёт о качестве), публичный словарь (SSR) и страница «Как собирается мёд».
**Приёмка:** внешний разработчик по документации делает первый успешный запрос за < 10 минут (проверяется жюри-агентом «с нуля»); вебхуки подписаны и повторяются; страницы словаря индексируемы.
**Жюри:** архитектура, безопасность, заказчик, QA.

### Альфа-пилот (веб + бот, 5 школ)
Реальные классы (город, село, школа с обучением на башкирском). Цели: проверить онбординг учителя, удержание недели, качество голосов детей, нагрузку на экспертов. Еженедельные сессии с учителями, наблюдение за уроками, опрос детей (с согласия родителей).

### Бета-пилот (все каналы, 15–20 школ)
Добавляются мобильные приложения (тестовые сборки: TestFlight, внутреннее тестирование в магазинах), урок-битвы, рейтинги. Цели: калибровка порогов консенсуса на экспертной разметке 2 000 вариантов, проверка стабильности, сбор отзывов. Итог — отчёт пилота с метриками против целей `00-vision.md`.

### M11. Укрепление
**Объём:** исправления по итогам пилотов; аудит безопасности и внешний пентест; нагрузочное тестирование на целевой профиль (60 тыс. одновременных); аудит доступности; SLO и алерты; учения по восстановлению из резервной копии; публикация в магазинах (ревью магазинов занимает время); производство контента курса до полного объёма 1-го года; открытый «марафон» для взрослых и диаспоры (обкатка нагрузки без школ).
**Жюри:** все.

### M12. Обучение учителей и релиз-кандидат
**Объём:** видеоинструкции, методические рекомендации, выступления на педсоветах районов, горячая линия поддержки, релиз-кандидат, заморозка функциональности.
**Жюри:** заказчик, продукт, QA.

### M13. Запуск 1.0
Публичный запуск, стартовый сезон лиг школ. Дежурства команды в первые 2 недели, ежедневный разбор метрик.

## 3. Общий Definition of Done для любой вехи

1. Функциональность из «Объёма» реализована, критерии приёмки выполнены и подтверждены тестами или воспроизводимой демонстрацией (скрипт `docs/demo/Mx.md`).
2. Тесты: модульные для доменной логики (покрытие доменных модулей ≥ 80%), контрактные для API, e2e для ключевых сценариев вехи; все тест-векторы зелёные на всех платформах.
3. `openapi.yaml` обновлён, клиенты перегенерированы, ломающих изменений нет (или новая версия).
4. Документы обновлены: затронутые разделы `docs/`, новые ADR, `docs/STATUS.md`.
5. Безопасность: нет секретов в коде, нет ПДн в логах, новые эндпоинты покрыты тестами авторизации.
6. UX: у новых экранов есть все состояния (загрузка/пусто/ошибка/офлайн), тёмная тема, крупный шрифт, подписи для экранных читалок.
7. Башкирский текст в интерфейсе и контенте либо проверен носителем, либо помечен `needs_native_review` и попал в список для владельца (`docs/native-review-queue.md`).
8. Гейт жюри пройден (`10-jury-loop.md`).

## 4. После 1.0 (R2/R3)

Порядок развития после запуска:
1. Говорение (распознавание на основе открытых моделей), голосовой корпус, AI-собеседник в ограниченных сценариях, банк заданий учителя, SDK-примеры API.
2. Интеграция с региональным электронным дневником / ФГИС «Моя школа» (при наличии условий), терминологические комиссии Фонда.
3. Морфологическая обратная связь, системная клавиатура-расширение, собственная MT-модель на корпусе (с публикацией метрик), курс для взрослых/диаспоры.
4. Далее — тиражирование движка на другие языки народов России (татарский, чувашский, удмуртский…) как платформы — отдельная возможность финансирования.
