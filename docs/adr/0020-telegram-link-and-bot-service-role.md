# ADR 0020. Привязка Telegram по подписи initData и служебная роль `service` для бота

- Статус: принято (M2 «Играбельный продукт», вне плана — по просьбе владельца; часть объёма M8). Дополнено: вход в Mini App по
  привязке (`POST /auth/telegram`) и одноразовый код привязки с сайта — реализованы.
- Связано: ADR 0007 (канально-независимый бот), 0014 (владение таблицами), 0015 (сессии), 0017 (авторизация), CLAUDE.md, правила 1, 4, 5, 13

## Контекст
Каркас Mini App (`/miniapp`) уже работает: вход — по QR-карточке через BFF, `initData` веб не отправлял. Владелец попросил настоящего
бота: `/start` с кнопкой «Учиться», напоминание о серии раз в день по согласию и привязку чата к аккаунту.

Чтобы напоминать, нужно знать две вещи:
- какой чат Telegram принадлежит какому аккаунту;
- у кого сегодня серия под угрозой.

Серия — в модуле `progress`. Бот — отдельное приложение (`apps/bot`), в чужие таблицы ему нельзя (правило 4).

В `docs/06` §7 и в роадмапе M8 привязка описана «одноразовым кодом из приложения». В Mini App есть способ проще: Telegram подписывает
`initData` токеном бота, и в подписанных данных есть `user.id` — он же `chat_id` личного чата с ботом.

## Решение
1. **Привязка — по подписи initData**, без одноразового кода.
   - Mini App после входа один раз за запуск отправляет `initData` как есть в `POST /api/v1/telegram/link` (роли `student`, `adult`; политика `self`).
   - API проверяет подпись по алгоритму Telegram: HMAC-SHA-256 data-check-string ключом `HMAC-SHA-256("WebAppData", токен бота)`.
   - `auth_date` — не старше суток и не больше чем на 5 минут из будущего.
   - Подпись проверяется до разбора JSON пользователя. Из строки берётся только `user.id`.
   - Ошибки: подпись не сошлась — 422 `init_data_invalid`, строка старше суток — 422 `init_data_expired`, нет `TELEGRAM_BOT_TOKEN` — 503 `telegram_unavailable`.
   - Код — `apps/api/src/modules/telegram/init-data.ts`. Тест сверяет код с публичным вектором `@telegram-apps/init-data-node`.
2. **Вход в Mini App по привязке** — `POST /api/v1/auth/telegram` (роли `anonymous`), без карточки.
   - `initData` проверяется так же; из строки берётся `user.id`, чат ищется в `telegram_links`: найден — сессия выдаётся, как по
     личной карточке (`SessionsService.issue`); нет — 404 `chat_not_linked`, миниапп показывает обычный вход (карточку или «Учусь сам»).
   - Сотрудникам вход запрещён (403 `telegram_login_forbidden`), заблокированным — 401 `account_blocked`. Не чаще 10 входов в час
     на чат. Логика — `identity/telegram-login.service.ts` (модуль `identity`), поиск привязки — через публичный интерфейс `telegram`.
3. **Одноразовый код привязки для веба без Mini App — реализован** (то, что в `docs/06` §7 описано «кодом из приложения»).
   - `POST /api/v1/me/telegram/link-code` (роли `student`, `adult`): код 8 знаков без похожих 0/O и 1/I, живёт 10 минут в Valkey,
     новый гасит прежний, не чаще 1 в минуту.
   - `POST /api/v1/telegram/bot/chats/link-code/redeem` (роль `service`): бот гасит код из `/start <код>`; погашение атомарно
     (`GETDEL`), привязка — той же upsert-семантикой, что `/telegram/link`. Брут-форс — 10 попыток в час на чат.
4. **Мост Mini App** (`telegram-bridge.ts`) держит `initData` только в памяти вкладки, в приватном поле `#initData`.
   - Строка убирается из адреса сразу, в `sessionStorage` и параметры запуска не попадает.
   - `takeInitData()` отдаёт её один раз. `TelegramProvider` вызывает его, как только появилась сессия.
   - После перезагрузки страницы хеша нет — привязка ждёт следующего открытия Mini App.
5. **Модуль `telegram`** в API, таблица `telegram_links` (миграция `0007_telegram`). Колонки:
   - `chat_id` — ключ, `bigint > 0`, только личные чаты;
   - `account_id`;
   - `reminders_enabled` — по умолчанию `false`, только по согласию;
   - `reminder_hour` — 8–20 по Уфе;
   - `last_reminded_on`;
   - `linked_at` и служебные метки времени.

   Ничего из профиля Telegram не хранится. Один чат — один аккаунт: повторная привязка переносит чат. У аккаунта может быть несколько чатов.
6. **Бот не хранит ничего сам.** Настройки напоминаний живут в модуле `telegram`, бот читает и меняет их служебными операциями. Бот можно
   перезапускать и переносить без своей базы.
7. **Служебная роль `service`** вместо доступа к чужим таблицам. Операции бота:
   - `GET` / `DELETE /api/v1/telegram/bot/chats/{chatId}`;
   - `PUT /api/v1/telegram/bot/chats/{chatId}/reminders`;
   - `POST /api/v1/telegram/bot/chats/link-code/redeem` — погашение кода привязки из `/start <код>`;
   - `POST /api/v1/telegram/bot/reminders/claim`.

   В контракте у них `x-access: { roles: [service] }` и `security: [{ serviceToken: [] }]` — заголовок `X-Service-Token`. Проверка —
   централизованно в `AccessControl` (хук `onRequest`, до разбора тела), как у остальных ролей:
   - верный секрет (`BOT_SERVICE_TOKEN`, сравнение за постоянное время) — пропуск;
   - действительный access-токен пользователя — 403;
   - иначе — 401;
   - секрет не задан — служебные операции закрыты для всех.

   Правило контракта (`access-rules.mjs`): роль `service` — только одна и только со схемой `serviceToken`, схема — только у неё.
   `X-Service-Token` не входит в разрешённые заголовки CORS: из браузера его не послать. В production dev-секрет запрещён проверкой конфигурации.
8. **«Кому напомнить» решает API.** `claim` отбирает чаты, где:
   - напоминания включены;
   - по Уфе наступил выбранный час;
   - ещё не тихие часы (21:00–08:00, `docs/02` §8);
   - сегодня ещё не напоминали;
   - серия аккаунта под угрозой: она есть, но цель дня сегодня не выполнена.

   Серию модуль `telegram` получает через публичный метод `ProgressService.streaksAtRisk(accountIds, now)`, таблицы `progress` не читает.
   Выданные чаты сразу отмечаются условным `UPDATE` (`last_reminded_on = сегодня`), так что двойного напоминания за сутки не будет даже при
   повторных или параллельных вызовах. В ответе — только `chat_id`.
9. **Бот** (`apps/bot`, grammY, long polling) раз в `BOT_REMINDER_INTERVAL_SECONDS` вызывает `claim` и отправляет одинаковый текст без ПДн:
   «Пчела скучает: сегодня ещё нет сот. Загляни на тропу!» — с кнопками «Учиться» и «Выключить напоминания».
   - Telegram ответил «заблокирован», «чат не найден» или «пользователь удалён» — бот отвязывает чат (`DELETE`), данных не остаётся.
   - В логах бота — только счётчики, без `chat_id`.
   - Клиент API бота — openapi-fetch по сгенерированным типам контракта.

## Последствия
- Модули не читают чужие таблицы. Бот — обычный клиент API со своей ролью. Новая служебная операция появляется так же — в `openapi.yaml`
  со строкой в матрице авторизации.
- `TELEGRAM_BOT_TOKEN` нужен и боту, и API: API проверяет им подпись. Без токена бот не стартует с понятным сообщением, привязка отвечает 503,
  остальной продукт работает.
- Привязка в Mini App происходит молча после входа. Напоминания при этом не включаются — только командой или кнопкой в боте.
- Перехваченная строка `initData` годится сутки. С ней можно привязать чужой чат к своему аккаунту — тогда напоминания без ПДн уйдут в
  чужой чат. Раскрыть данные аккаунта так нельзя: ответы бота и `claim` не содержат ничего, кроме `chat_id`. Вход по `initData` не
  расширяет это: сессия выдаётся, только если чат уже привязан к аккаунту.
- Коды привязки живут в Valkey (без таблиц и миграций): ключ `tg-link-code:<код>` со значением-аккаунтом, TTL 10 минут, погашение
  `GETDEL`; выпуск — 1 в минуту на аккаунт, перебор — 10 в час на чат.
- Не сделано (M8): вебхуки вместо long polling, очередь исходящих с повторами при 429, снижение частоты после 3 дней без реакции
  (`docs/02` §8), учебное время школы как тихие часы, фраза дня, дуэли и команды учителя в боте, дайджест родителя.

## Альтернативы
- **Одноразовый код привязки** (`docs/06` §7). Пользователю нужно вводить код, а в Mini App подписанный `user.id` уже есть. Реализован
  (2026) как путь для обычного веба и приложений — без Mini App: `/start <код>` боту, код 8 знаков на 10 минут, хранится в Valkey.
- **Бот хранит настройки сам** (файл или своя база). Это второе хранилище с `chat_id`, второй путь удаления и состояние, которое теряется
  при переезде. Отказались.
- **API сам рассылает напоминания** (токен у него есть). Логика канала разошлась бы между ботом и API — против ADR 0007.
- **Анонимная операция с проверкой секрета в обработчике** (как `X-Poll-Token`). Контракт описывал бы операцию как публичную, а матрица
  авторизации ждала бы пропуска анонима. Отказались в пользу явной роли.
