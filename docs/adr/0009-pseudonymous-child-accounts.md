# ADR 0009. Псевдонимные детские аккаунты (privacy by design)

- Статус: принято (M0, реализация — M1); правка 2026-11-10 — исключение для входа по почте (ADR 0022 §10)

## Решение
Ребёнок входит по QR-карточке или коду класса с PIN и получает ник из генератора. ФИО, дата рождения, телефон, e-mail, фото, геолокация и национальность не собираются; связка «ник ↔ ученик» есть только у учителя (рукописная подпись на карточке). Персональные данные взрослых — в отдельной схеме `pii` (создана миграцией `0000_init`).

**Правка 2026-11-10 (решение владельца).** Ребёнок может привязать почту для входа с другого устройства
(`POST /me/email`, ADR 0022 §10) — единственное отступление от «не собираем e-mail у детей». Сам адрес при этом
не хранится: в `credentials` лежит только HMAC-хеш (ключ поиска входа), строки в `pii` для детских аккаунтов
по-прежнему нет (триггер миграции 0002 сохранён), адрес не возвращается в `Me` и не попадает в логи. До
продакшена — вопрос согласия родителя (152-ФЗ): привязку делает сам ребёнок по коду из письма, т.е. подтверждает
владение адресом; юридическую процедуру решить до запуска.

## Последствия
Утечка базы не раскрывает личности детей. Нет персональных данных в логах, аналитике, пушах, сообщениях бота и промптах.
