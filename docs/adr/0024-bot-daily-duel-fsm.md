# ADR 0024. Ежедневное задание в Telegram-боте: FSM-диалог в БД

- Статус: принято (M2 «Играбельный продукт», вне плана — решение владельца «допилить проект по ТЗ хакатона»; часть объёма M8)
- Связано: ADR 0007 (канально-независимое ядро бота), 0014 (владение таблицами), 0019 (duel-v0), 0020 (привязка initData и роль `service`), 0023 (словарь Фонда), CLAUDE.md правила 4, 9, 13

## Контекст

ТЗ хакатона (§7) требует FSM-диалог бота для ежедневных заданий с состоянием в БД и поддержкой `/start` и `/cancel`.
Каркас бота (ADR 0020) умеет `/start`, `/help`, `/remind*`, `/unlink` и кнопку Mini App — задания в чате нет: по плану
сценарии бота были в M8. Владелец попросил закрыть это до показа.

Ежедневное задание по ТЗ (§4.3) — «подтвердить корректный перевод или исправить его». В «ТелеТау» это дуэль
«Помоги языку» (ADR 0019): исходник на русском и два засвидетельствованных башкирских варианта — «Какой перевод
лучше?». В вебе дети голосуют в уроке, взрослые и учителя — в разделе «Помогите языку». В боте задание дня должно
быть доступно любому связанному аккаунту (ученик, взрослый, учитель) — а операции `/corpus/*` детям закрыты.

## Решение

1. **FSM — таблица `telegram_dialogs` в модуле telegram** (ADR 0014: таблица модуля, чужие модули — через сервисы).
   Активный (`issued`) диалог один на аккаунт; после ответа — `answered`, после `/cancel` — `cancelled`. Выдача
   идемпотентна: повторный вызов возвращает тот же диалог — перезапуск бота и повторные нажатия ничего не теряют
   (состояние не в памяти процесса и не в callback_data).
2. **Одна дуэль в сутки по Уфе на аккаунт** (`done` в ответе выдачи, `empty` — нерешённых дуэлей нет). Задание дня —
   ритуал из ТЗ; сколько угодно дуэлей остаётся в вебе (уроки детей, «Помогите языку» взрослых).
3. **Служебные операции роли `service`** (ADR 0020 §5, `X-Service-Token`): `POST /telegram/bot/chats/{chatId}/daily-duel`
   (выдать), `POST /telegram/bot/dialogs/{dialogId}/answer`, `POST /telegram/bot/chats/{chatId}/daily-duel/cancel`.
   Аккаунт берётся из привязки чата; группа голосующего — из типа и ролей аккаунта на момент голоса (порт
   `AccountsPort.voterView`), как в вебе.
4. **Голос — через публичный `ConsensusService.recordVote`** в транзакции: журнал `judgments` (только вставка,
   правило 9), пересчёт `item_state` по duel-v0, мёд pending → final через `ProgressService` — тот же путь, что в
   вебе. Новый контекст голоса — значение `telegram` у `judgments.context` (миграция аддитивна). `judgmentId`
   генерирует API при выдаче диалога.
5. **Выбор дуэли** — новая операция публичного сервиса `ConsensusService.pickDailyDuel(voter)`: одна свежая
   (не голосованная) дуэль курса, сначала исходники в статусе `voting`.
6. **Кнопки ответа несут `dialogId`** (`dd:<uuid>:<choice>`, ≤ 64 байт Bot API): состояние диалога — в БД, но кнопка
   указывает, к какому сообщению относится. Голос по устаревшей кнопке (диалог уже отвечен или отменён) не
   применяется к новому диалогу: `409 dialog_closed` / `already_voted` / идемпотентный replay.
7. **Повторное нажатие той же кнопки** — тот же ответ без новой записи: replay по `judgmentId`, как у попыток урока.
8. **Распределение голосов в боте не показывается** (защита от конформизма, docs/03 §4a): ответ — только «Голос
   учтён». Голоса по группам — в вебе после своего голоса и в выгрузках ролей `fund`/`ministry`.
9. **Привязка и отвязка чата закрывают диалоги чата**: `/unlink` удаляет строки диалогов, повторная привязка чата к
   другому аккаунту отменяет выданные — голос не может уйти от прежнего владельца привязки.
10. **Спорные случаи — отдельный список** (ТЗ §4.4/§5, опциональный квант): `GET /fund/escalated` — исходники
    `item_state.status = escalated` с голосами по группам; раздел в консоли Фонда. Передача экспертам (УФИЦ РАН) —
    вне хакатона, список — задел (ТЗ §8).

## Последствия

- Миграция `0014_tz_daily_duel`: `ALTER TYPE consensus_judgment_context ADD VALUE 'telegram'` + таблица
  `telegram_dialogs`. Аддитивно, `pnpm contracts:check` пройдёт без базовой версии.
- Дети голосуют вне урока только через бота (и только одну дуэль в сутки) — осознанное отличие от «дети голосуют в
  уроке» из контракта `/corpus/*`: новый контекст в журнале виден отдельно, при желании исключается пересчётом.
- Бот остаётся канально-независимым (ADR 0007): `/daily` и `/cancel` — в `core/scenarios.ts`, ничего от Telegram;
  long polling — без HTTPS (ТЗ §7 не требует публичного адреса).
- `answer` считает `latencyMs` сам (время от выдачи до ответа) — в запросе только `choice`.
- Правило 13: в сообщениях бота — контент дуэли и статусы, ничего из профиля; в таблице диалогов — `chat_id`, id
  аккаунта и ссылки на контент.
- Сценарии бота из M8 частично сдвинуты в M2 — роадмап M8 сужается до Mini App-специфики и входа по Telegram.
