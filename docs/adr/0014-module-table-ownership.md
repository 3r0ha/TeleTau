# ADR 0014. Владение таблицами модулями

- Статус: принято (M0, раунд 2 — находка жюри M0-05; правила проверки дополнены в раунде 3 — M0-R3-04)

## Контекст
ADR 0001 обещает: модуль не читает чужие таблицы, иначе выделить его в сервис будет дорого. В раунде 1 жюри показало, что обещание не проверялось. Общий `src/db/schema.ts` и глобальный пул позволяли любому модулю импортировать любую таблицу, и CI оставался зелёным.

## Решение
1. Таблицы модуля описываются только в `src/modules/<m>/<m>.schema.ts`. `drizzle.config.ts` собирает схемы по маске `./src/modules/*/*.schema.ts`. Файлы `*.schema.ts` и `schema.ts` вне модулей запрещены.
2. `index.ts` модуля не реэкспортирует его схему. Чужие модули работают через сервисы и доменные события, а не через таблицы.
3. `src/infra`, `src/common`, `src/db`, `src/config` не импортируют `src/modules/**`, поэтому лазеек для реэкспорта нет.
4. Проверка — `apps/api/scripts/boundaries.mjs` в `pnpm lint`, на каждое правило есть тест в `apps/api/test/boundaries.test.ts`. Скрипт проверяет:
   - **(а)** модуль импортирует другой модуль только через его `index.ts`;
   - **(б)** `src/{infra,common,db,config}` не импортируют `src/modules/**`;
   - **(в)** файлы `*.schema.ts` и `schema.ts` лежат только в `src/modules/<m>/`;
   - **(г)** `index.ts` модуля не отдаёт его схему ни напрямую, ни транзитивно: `export * from`, `export {…} from`, «импорт, затем `export { … }`», значение-псевдоним (`export const t = accounts`, `export const tables = { accounts }` / `{ ...schema }`, `export default schema`) в любом файле цепочки реэкспорта (M0-R2-04, M0-R3-04);
   - **(д)** `pgTable`, `pgSchema`, `pgEnum`, `pgView`, `pgMaterializedView`, `pgSequence`, `pgTableCreator` вызываются только в `*.schema.ts`; вне них эти функции нельзя и импортировать из `drizzle-orm/pg-core`, в том числе под другим именем (`import type` — можно);
   - **(е)** нет циклических импортов;
   - запуск через путь с пробелами, кириллицей и символическими ссылками не отключает проверку (M0-04, M0-R2-04).

   Это эвристика на регулярных выражениях. Выражение с вызовом (`new Repo(accounts)`, `make(accounts)`) утечкой не считается — это сервис, а не таблица. Намеренный обход (функция, возвращающая таблицу) статически не ловится. **Бэклог:** правило (г) через компилятор TypeScript — ни один экспорт `index.ts` модуля не имеет типа `PgTable`/`PgSchema` и не содержит их.

## Последствия
- `db:generate` требует хотя бы одну схему модуля (первые появятся в M1).
- Сырой SQL к чужой таблице статически не ловится. **Следующий шаг (до M4):** отдельная схема Postgres и роль на модуль (`identity`, `corpus`, `consensus`…). Роль модуля получает права только на свою схему, а пул модуля подключается под своей ролью. Тогда граница защищена и в рантайме.

## Альтернативы
- Общая схема с ревью вручную — отклонено: не масштабируется на работу AI-агентов.
- Сразу схемы и роли Postgres на модуль — отложено: в M0 у модулей ещё нет таблиц.
