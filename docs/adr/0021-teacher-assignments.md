# ADR 0021. Задания учителя классу — отдельный модуль `assignments`

- Статус: принято (M2 «Играбельный продукт», по просьбе владельца; часть объёма M9 «дашборд учителя: задания, отчёты»)
- Связано: ADR 0009 (псевдонимные аккаунты детей), 0014 (владение таблицами), 0017 (авторизация), CLAUDE.md, правила 1, 4, 5

## Контекст
Учителю нужно дать классу задание со сроком и видеть, кто его сделал: урок тропы, «Испытание места» или «Повторить слова».
Задание видно ученику на тропе («Задание учителя: … до пт») и засчитывается, когда урок пройден. Учитель видит выполнение
по номерам мест: сделали, ещё нет, просрочили. Одновременно у класса — одно-два задания.

Варианты размещения:
- в `progress` — у него уже есть прохождение уроков. Но `progress` знает только «пройден ли узел вообще», а задание
  засчитывается прохождением **после выдачи**; к тому же у задания свой жизненный цикл (выдать, снять, срок);
- в `learning` — он видит завершение забега, но это верхний модуль: прогресс класса и задания ему не нужны;
- **отдельный модуль** `assignments`.

## Решение
1. **Модуль `assignments`** (`apps/api/src/modules/assignments`), граф: `assignments → org, content, progress`;
   `learning → assignments`. Модуль не знает о `learning`, циклов нет (`boundaries.mjs`).
2. **Таблицы** (миграция `0009_assignments`):
   - `assignments` — класс, учитель, вид (`lesson | place_test | review`), узел тропы (у `review` нет — CHECK), снимок
     названия и места, срок `due_on` (дата по Уфе, включительно), `cancelled_at`;
   - `assignment_completions` — (задание, аккаунт) → забег и момент выполнения; только вставка, повтор урока не
     перезаписывает момент.
3. **Выполнение** пишет `learning` в транзакции завершения забега (`AssignmentsService.recordCompletion`): подходят
   незаснятые задания классов ученика, выданные до момента завершения. Урок или «Испытание» — тот же узел; повторение
   слов — задание `review`. После срока выполнение тоже засчитывается — как «сделано после срока» (`done_late`).
   Урок или «Испытание», **пройденные ещё до выдачи**, тоже засчитываются (момент — первое прохождение, через
   `ProgressService.firstPasses`, граф `assignments → progress`): учитель задаёт урок, а не «пройди ещё раз», и не видит
   «ещё нет» у тех, кто его уже прошёл. Повторение слов — только после выдачи.
4. **Статусы места** считаются при чтении: `done` (до конца дня срока по Уфе), `done_late`, `todo`, `overdue`.
   Места — ученики на местах класса в момент запроса (новенький тоже получает задание).
5. **Тропа ученика** (`GET /course`): поле `assignments` — активные задания классов ученика (просроченные не показываются —
   ребёнка не стыдим). Заданный узел открытого юнита открыт (`open`), даже если предыдущие уроки не пройдены: иначе
   задание невыполнимо. «Повторить слова», когда срок ни одного слова не наступил, повторяет ближайшие по сроку слова
   (FSRS-6 учитывает раннее повторение).
6. **Ограничения**: не больше двух активных заданий на класс (409 `assignment_limit`), одинаковое активное — 409
   `assignment_exists`; срок — от сегодня до 28 дней; задать можно только урок или «Испытание» открытого юнита. Выдача —
   под рекомендательной блокировкой класса, с `Idempotency-Key`.
7. **Операции** (`x-access: teacher, class-teacher`, строки матрицы авторизации): `GET/POST /classes/{id}/assignments`,
   `DELETE /classes/{id}/assignments/{assignmentId}` («снять» — задание пропадает у всех, выполнение остаётся в прогрессе).
   Ответы — по номерам мест, без ников и ПДн; ники учитель берёт из `GET /classes/{id}` (ADR 0009).

Рядом, в модуле `progress`: карточка ученика `GET /classes/{id}/seats/{seat}/progress` (уроки с лучшей точностью, слова,
серия, голоса, мёд, последние дни) и `SeatProgress.wordsLearned` для отчёта. Отчёт CSV и печатная версия «Прогресса» — на
клиенте из этих же данных, нового API не требуют.

## Последствия
- Нативные клиенты получают задания из `GET /course` без новой операции; кабинет учителя на iOS/Android — позже (M6/M7).
- «Снять» — мягкое удаление: история выдачи остаётся в базе; восстановления в интерфейсе нет.
- Задания по темам учебника, миссии и банк заданий (docs/01 §3.4) — M9, на этой же таблице (новые `kind`).
