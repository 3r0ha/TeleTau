# Демо M1 — Доступ и организации

Сценарий повторяет человек или жюри. Названия экранов и кнопок ниже — как в интерфейсе.

Автоматическая версия — `pnpm e2e` (Playwright, `e2e/tests/m1-demo.spec.ts`): весь сценарий §1–§6 в браузере против настоящего стека, у каждого участника — свой контекст браузера.

## 0. Подготовка

```sh
pnpm dev
```

Команда:
- поднимает Docker-стек проекта;
- применяет миграции;
- загружает справочник районов и школ РБ с демо-школами;
- запускает api, web и console.

Адреса — из `.env`: web `http://localhost:3000`, console `http://localhost:3100`, api `http://localhost:4000/api/v1/health`.

Ученику и учителю нужны разные браузеры или профили браузера: сессия хранится в cookie сайта.

## 1. Учитель регистрируется

1. Web → «Я учитель или взрослый» → «Электронная почта» → «Получить код».
2. Экран «Введите код». Письмо не отправляется: в демо-режиме (`AUTH_DEMO_OTP=0000`) код всегда **0000**, экран так и пишет («Демо: код 0000»). После четвёртой цифры вход выполняется сам.
3. «Примите условия». У каждого документа есть ссылка «Читать» — она открывает страницу веба `/legal/<вид>/<версия>` с текстом этой версии. Кнопка «Принять». Версия принятого документа фиксируется в `consents`.
4. «Расскажите о себе»: «Фамилия, имя, отчество», «Должность» → «Дальше».
5. «Выберите район»: найти и выбрать район → «Дальше». Для демо подойдёт «Демо-район (для проверки)».
6. «Выберите школу»: найти по названию или номеру → «Отправить заявку». Экран «Заявка на проверке».

## 2. Модератор подтверждает учителя

1. Console → «Вход сотрудника» → «Рабочая почта» `moderator@demo.teletau.local` → «Получить код».
2. «Код из письма»: **0000**.
3. «Код из приложения»: 6 цифр TOTP. Секрет демо-модератора и команда, которая печатает код без телефона, — в `apps/api/data/README.md`.
4. «Заявки учителей», вкладка «На проверке» → «Одобрить» у нужной заявки. Появится уведомление «Заявка одобрена: …».
5. «Журнал аудита» → «Действие»: «Заявка учителя одобрена». В таблице — запись о решении.
6. У учителя страница «Заявка на проверке» сама открывает кабинет «Мои классы» (опрос раз в 10 с).

## 3. Учитель создаёт класс и печатает карточки

1. «Мои классы»: первый вход — карточка «Первый урок» с тремя шагами → «Создать класс» → диалог «Новый класс»: класс 5, «Литера» Б, программа «Родной язык» → «Создать класс». Откроется страница класса «5 «Б»» с шагами «Первый урок».
2. Шаг 2 — «Выпустить карточки» → «Сколько карточек»: 24 → «Выпустить 24 карточки» → «Карточки готовы» → «Скачать PDF».
3. PDF: 3 страницы карточек (по 8 на странице) и бланк согласия родителя. На карточке:
   - класс;
   - номер места;
   - QR;
   - строка «Имя» (имя вписывает учитель).

   ПДн нет. Файл можно скачать 30 минут, потом невыданные карточки перевыпускаются.

## 4. Ученик входит по QR

1. Другой браузер или устройство → web → «У меня есть карточка или код» → «Покажи карточку камере».
2. «Сканировать карточку» и навести камеру на QR. Без камеры подойдёт «Загрузить фото карточки» (снимок экрана с QR тоже годится). В QR только код карточки `TT1.…`, без ссылки: системная камера телефона не открывает по нему браузер с секретом. Так закрыта находка M1-02, ADR 0016 §2. Старый маршрут `/q` показывает только инструкцию «У меня есть карточка или код» → «Сканировать карточку».
3. «Выбери ник»: один из трёх вариантов или «Другие варианты» → «Выбрать» → «Ты в классе 5 «Б»».

   Весь путь — меньше 30 с. Ни имени, ни e-mail, ни телефона не спрашивают.
4. У учителя на странице класса без перезагрузки появляются:
   - плитка «№01» с ником;
   - уведомление «№01 · <ник> — в классе».

## 5. Вход по коду класса (без карточки)

1. Учитель → «Показать код класса». Код вида `ABC-DEF` во весь экран, таймер «Действует ещё 15:00» и шаг «Открой сайт <адрес> и нажми «У меня есть карточка или код»». Рядом QR со ссылкой на главную страницу сайта: камера телефона откроет сайт. В этом QR только адрес, секретов в нём нет (M1-44).
2. Ученик → «У меня есть карточка или код» → «Ввести код класса» → «Введи код класса» → «Дальше» → «Выбери ник» → «Отправить заявку» → «Ждём, пока учитель подтвердит».
3. Учитель → «Закрыть код класса»: код гаснет на сервере сразу (`DELETE /classes/{id}/join-code`, M1-49). Новый ученик с тем же кодом увидит «Код не подходит…», а уже поданные заявки остаются. Учитель → баннер «1 ученик ждёт подтверждения» → «Посмотреть» → «Принять». Ученик сам попадает на экран «Ты в классе 5 «Б»».

   В классе не больше 40 ожидающих заявок; с одного устройства ждёт одна заявка — новая заменяет прежнюю.

   Ему выдаётся новое место без карточки: на плитке — «Без карточки».
4. Если до входа ученика учитель отозвал согласие места или класс ушёл в архив, страница ожидания покажет «Вход закрыт» или «Класс закрыт» с кнопкой «Выйти». Повторный опрос заявки сессию уже не выдаст (M1-35).

## 6. Защита

1. **Чужой класс.** Второй учитель (повторить §1–2 с другим e-mail) открывает класс первого по прямой ссылке `/teacher/classes/<id>`. Ответ — «Нет доступа», API отвечает 403.
2. **Повтор refresh-токена.** Повторно предъявить старый refresh-токен (команды — в `apps/api/test/README.md`). Вся сессия отозвана, в «Журнале аудита» — «Повтор refresh-токена: сессия отозвана».
3. **Перевыпуск карточки.** Учитель → плитка «№01» → «Перевыпустить карточку» → ещё раз «Перевыпустить карточку» (подтверждение) → «Скачать PDF» с новой карточкой.
   - Старая карточка: «Не получилось войти» — «Эта карточка больше не действует: учитель выдал вместо неё новую.» Ученик, который уже вошёл старой карточкой, выходит на всех устройствах (`session_revoked`, M1-03).
   - По новой карточке ученик входит сразу в класс: ник и место сохранились.
   - Для места, занятого по коду класса (карточки ещё нет), кнопка называется «Выпустить карточку». Ученик тоже выходит на всех устройствах и дальше входит по новой карточке (M1-37). Повторный опрос старой заявки по коду сессию не выдаёт.
4. **Отзыв согласия.** Плитка «№01» → «Отметить согласие родителя» → «Отозвать согласие» → ещё раз «Отозвать согласие» (подтверждение).
   - Перед отзывом диалог предупреждает: «Вход на место будет закрыт, ученик выйдет на всех устройствах». После — уведомление «Согласие №01 отозвано» и метка «Согласие отозвано».
   - Открытая сессия ученика завершается. Повторный опрос заявки по коду класса тоже не выдаёт сессию (M1-35).
   - Вход по карточке: «Не получилось войти» — «Вход по этой карточке закрыт. Подойди к учителю.»

## Автоматическая проверка

```sh
pnpm e2e                    # весь сценарий; повтор — pnpm e2e --repeat-each=3
bash scripts/verify.sh      # всё, включая e2e; без него — --skip-e2e
```

`pnpm e2e` (`e2e/run.mjs`):
1. берёт окружение как `pnpm dev`: `.env` и недостающие ключи из `.env.example`;
2. поднимает Docker-стек проекта или использует уже поднятый;
3. собирает api, web и console (кеш turbo);
4. применяет миграции и загружает справочник;
5. запускает Playwright. Он сам поднимает api, web и console на портах из `.env` и после прогона их останавливает.

Порты api, web и console должны быть свободны: `pnpm dev` на время прогона нужно остановить. Браузер — уже скачанный Chromium из кеша Playwright.

| Тест | Что проверяет |
|---|---|
| `e2e/tests/m1-demo.spec.ts` | §1–§6 (кроме §6.2 — его проверяет `apps/api/test/integration/m1-flow.test.ts`). QR из скачанного PDF декодируется (`pdfjs-dist` + `jsqr`) и проходит `parseQrPayload`. Вход по фото карточки («Загрузить фото карточки», распознаёт страница). Замер «ссылка → «Ты в классе»» < 30 с и «ник выбран → учитель видит» ≤ 5 с. axe (WCAG 2.2 AA, без серьёзных нарушений) на ключевых экранах веба и консоли |
| `e2e/tests/proxy-ip.spec.ts` | Лимит «20 неверных попыток QR с IP за минуту» через BFF Next.js считается по IP ученика (`X-Forwarded-For`, `TRUST_PROXY=loopback`): 21-я попытка — 429, другой ученик за тем же сервером Next не заблокирован |

## Проверено

Каждый шаг воспроизведён на настоящем стеке: Docker и собранные api, web и console на портах из `.env`. `pnpm e2e` проходил без повторов и без единого падения: дважды по три прогона подряд, затем в `scripts/verify.sh` на Node 24 и на Node 26. Цифры — из прогонов на этом компьютере: Apple Silicon, headless Chromium.
