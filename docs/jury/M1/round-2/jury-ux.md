## Находки

### [P2] Ошибки проверки в формах взрослого не слышны читалке: фокус остаётся на кнопке, сообщение не в живой области
- **Где:**
  - `packages/ui/src/TextField.tsx:22-30` — ошибка выводится обычным `<p class="kz-field__error">`, без `role="alert"` и без `aria-live`;
  - формы, где фокус не переносится:
    - `apps/web/app/teacher/login/OtpLogin.tsx:43` — адрес почты;
    - `apps/web/app/teacher/apply/page.tsx:112-118` — шаг 1 заявки;
    - `apps/web/app/teacher/CreateClassDialog.tsx:89` — литера класса;
    - `apps/web/app/teacher/classes/[id]/IssueCardsDialog.tsx:56` — число карточек.
- **Доказательство:** `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r2/out/field-errors.json`. После нажатия активным остаётся элемент `BUTTON` («Получить код», «Дальше», «Создать класс», «Выпустить карточки»). Текст ошибки виден, но `live: false`. Для сравнения: в коде класса ученика и в одноразовом коде учителя фокус возвращается в ячейку, к которой ошибка привязана через `aria-describedby`, — там читалка ошибку объявит.
- **Почему это проблема:** WCAG 4.1.3 (AA) и 3.3.1. Незрячий учитель на главном пути (вход, заявка) нажимает кнопку и ничего не слышит. Он не понимает, идёт ли загрузка или что-то не так.
- **Предлагаемое исправление:** при ошибке проверки переносить фокус на первое неверное поле. У полей уже есть `aria-invalid` и `aria-describedby`, поэтому читалка прочитает ошибку. Второй вариант — показывать сводку ошибок в `role="alert"`. Добавить проверку в `apps/web/test/e2e/steps.spec.ts`.

### [P3] При шрифте 200 % на четырёх экранах взрослого появляется горизонтальная прокрутка; ссылка «К основному содержимому» выглядывает сверху
- **Где и доказательство:** настройка «размер шрифта» 200 % (`html{font-size:32px}`), ширина 375. Результаты — `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r2/out/font200-*.json`.
  - **Условия** (`font200-375-terms.png`): ширина страницы 523 px. Кнопка «Читать» уходит за край карточки и экрана. Причина — `.doc-list__text { flex: 1 }` без `min-width: 0` (`apps/web/app/globals.css:208-212`) и строка без переноса (`:191-199`).
  - **Ввод кода** (`font200-375-teacher-otp.png`): 440 px — адрес почты не переносится (`OtpLogin.tsx:127`).
  - **Профиль** (`font200-375-profile.png`): 451 px — почта в `dd`.
  - **Старая ссылка `/q`**: 382 px — слово «приложении» в заголовке.
  - **Ссылка пропуска на всех страницах**: при `top: -100px` (`packages/ui/src/ui.css:111`) и высоте 117 px нижние 17 px видны сверху белой полосой (`skiplink.json`, `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r2/shots/skiplink-200.png`).

  Тест проекта `modes.spec.ts:81` проверяет только 6 адресов, этих среди них нет.
- **Почему это проблема:** учитель 55 лет с увеличенным шрифтом в Chrome на Android прокручивает экран вбок, чтобы прочитать документ.
- **Предлагаемое исправление:**
  - `min-width: 0` и `flex-wrap: wrap` у строки документа;
  - `overflow-wrap: anywhere` у почты, `dd` и заголовков;
  - прятать ссылку пропуска через `transform: translateY(-100%)` вместо фиксированного отступа;
  - добавить четыре адреса в тест.

- **Профиль:** при офлайне `/me` скелетон показывается бесконечно, ни текста, ни повтора (`apps/web/app/teacher/profile/page.tsx:17,37-38` — ошибка `useTeacherGate` не обрабатывается). Снимок — `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r2/shots/state-profile-offline.png`.
- **Заявка, шаг 2:** районы не загрузились — «Нет связи с сервером…», но кнопки повтора нет, «Дальше» неактивна, спасает только перезагрузка (`apply/page.tsx:231`; то же у списка школ). Снимок — `state-apply-districts-offline.png`.
- **Выбор ника:** при ошибке «попробуй снова», но повтор спрятан в «Другие варианты» (`NicknamePicker.tsx:44-45`).
- **Ожидание проверки:** если `GET /teacher/verification` отвечает 500, страница молча показывает «Заявка на проверке» без данных и без ошибки (`pending/page.tsx:34`).

### [P3] Вход по коду класса: доска не говорит, где «открыть Кәрәҙ»
- **Где:**
  - `apps/web/app/teacher/classes/[id]/JoinCodeBoard.tsx:110` — шаг «Открой Кәрәҙ и нажми «Я ученик»»; адреса сайта на доске нет (grep по `PUBLIC_WEB_URL` в `apps/web/app` его тоже не находит);
  - `apps/web/app/q/page.tsx:23` пишет «Карточку сканируют в приложении», а карточка (`cards-pdf.ts:50-54`) — «Открой сайт …».
- **Почему это проблема:** код класса нужен как раз детям без карточки, то есть без напечатанного адреса. После M1-02 QR больше не открывает сайт, и адрес — единственный вход. Слова «сайт» и «приложение» для одного и того же путают ребёнка.
- **Предлагаемое исправление:** показывать на доске хост из `PUBLIC_WEB_URL` крупно. Везде писать одно слово — «сайт».

### [P3] «Назад» браузера и Android при открытом листе уводит со страницы, а не закрывает лист
- **Где:** `packages/ui/src/Dialog.tsx` — при открытии листа запись в истории не создаётся.
- **Доказательство:** `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r2/out/back-sheet.json`, `dialogs.json`. Открыт лист «Место №03» → `goBack()` → `/teacher`. Открыт «Новый класс» → `goBack()` → уход со страницы.
- **Почему это проблема:** на Android (Material 3, predictive back) «Назад» сначала закрывает лист. Учитель теряет открытую страницу класса.
- **Предлагаемое исправление:** при открытии листа делать `pushState`, по `popstate` закрывать лист. Экран «код на доску» — по желанию.

### [P3] Мелочи
- **Консоль, журнал аудита:** роли выводятся кодами — «сотрудник, moderator», «взрослый, teacher» (`apps/console/app/audit/page.tsx:150`, снимок `apps/web/test/screens/console-05-audit-1280.png`). Нужны русские названия ролей.
- **Ввод кода учителя:** на шаге «Введите код» заголовок вкладки остаётся «Вход для учителя · Кәрәҙ» (`/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r2/out/titles.json`, `teacher-otp`).
- **Код на доске:** `aria-label` стоит на `<span>` без роли (`JoinCodeBoard.tsx:99`). По ARIA 1.2 имя у элемента без роли запрещено, читалки его не обязаны читать. Нужен `role="text"`/`img` или скрытый текст с кодом через пробелы.

### Предложения (вкусовщина, не находки)
- **QR сайта на доске.** На доске и на плакате класса показать QR со ссылкой на корень сайта, без секрета: системная камера откроет сайт, дальше «Я ученик» → «Сканировать карточку». Это возвращает короткий путь, который потерялся из-за M1-02. Отдельно передать жюри безопасности: QR с простым текстом `TT1.…` системная камера телефона может предложить «найти в интернете». На устройстве не проверял.
- **Двуязычие.** Башкирский в интерфейсе по-прежнему только в бренде. Нужно первое двуязычное приветствие с `needs_native_review`.
- **«Пчёлка» в M2.** Маскот на экранах ввода кода и выбора ника, озвучка инструкций (§7).
- **Ячейки кода класса.** На широком экране можно делать 56 px в ширину: исключение 40–56 px нужно только при ширине до 375.

## Что сделано хорошо (≤ 5 пунктов)
1. **Исправления закреплены тестами.** `modes.spec.ts`, `steps.spec.ts` и `console.spec.ts` проверяют каждую находку M1-12…M1-16 и M1-30 в браузере. В моём прогоне: веб — 86 тестов прошли (54 снимка экранов пропущены без `TELETAU_SCREENS`), консоль — 5 из 5, мой собственный набор — 157 из 157.
2. **Доступность по axe и вёрстка на 320 px.** WCAG 2.2 A/AA и best-practice — 0 нарушений на 28 экранах в двух темах. На ширине 320 px горизонтальной прокрутки нет нигде. При «Уменьшении движения» не идёт ни одна анимация (`motion.json`).
3. **«Пчёлка» реализована целиком, от API до CSS.** Режим выставляется по номеру класса при каждом входе. Экраны до входа сразу крупные. Взрослым режим не ставится.
4. **Правильная механика шагов.** Шаг лежит в адресе, черновик — в `sessionStorage` и привязан к аккаунту. Фокус переходит на заголовок шага, заголовок вкладки меняется вместе с шагом.
5. **Бережные тексты для ребёнка.** «Уже уходишь?» с подтверждением выхода, «Не ждать и выйти», «Что дальше». Эмодзи в интерфейсе нет. В вебе Ҫ и Ҙ рисуются башкирской формой.

**Как проверял.** Веб и консоль запускались на портах 3255, 3277 и 3377 против моков API по контракту (`apps/web/test/e2e/mock-api.ts`); после прогона серверы остановлены. Изолированный Docker-стек не поднимал: сборка веба вшивает адрес API `localhost:4000`, а этот порт брать нельзя. Логику API для режимов проверил по коду; интеграционные тесты API не запускал, этот пункт стоит перепроверить жюри QA. `pnpm tokens:check` пересобирает сгенерированные файлы токенов; `pnpm codegen:check` подтвердил, что они не изменились. Других файлов проекта я не менял. Скрипты, данные и снимки — в `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r2/` (`tests/`, `out/`, `shots/`, `pdf/`).
