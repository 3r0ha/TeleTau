## Находки

### [P3] Отзыв согласия: текст не совпадает с тем, что делает сервер
- **Где:**
  - `apps/web/app/teacher/classes/[id]/SeatDialog.tsx:158` — «Вход по карточке №NN будет заблокирован, пока согласие не отметят снова.»;
  - там же, `:87` — тост «Согласие отозвано: вход по карточке №NN закрыт».
- **Доказательство:**
  - Место без карточки (ученик вошёл по коду класса), согласие дано → «Отозвать согласие». Диалог показывает «Карточка: Нет — вход по коду класса» и тут же «Вход по карточке №13 будет заблокирован». Файлы: `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r3/out/r3-seat-nocard.json` и `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r3/shots/seat-nocard-revoke-confirm.png`.
  - Сервер при отзыве делает больше. Он завершает все сессии ученика и закрывает вход и по карточке, и по коду класса: `apps/api/src/modules/consent/consent.service.ts:302-305`, `:335-337` (`revokeAllSessions(…, "consent_revoked")`).
- **Почему это проблема:** это тот же принцип, что в M1-37: интерфейс должен говорить, что произойдёт. Для места без карточки «вход по карточке» неверно. Ни в одном варианте не сказано, что ученик сразу выйдет на всех устройствах, хотя в предупреждении о перевыпуске это выделено жирным. Учитель может нажать кнопку посреди урока, не ожидая, что ученика выбросит.
- **Предлагаемое исправление:** писать «Вход на место №NN будет закрыт, **ученик выйдет на всех устройствах**…», если на месте есть ученик, а для места без ученика — «вход на место». Тост поправить так же. Добавить тест в `class-page.spec.ts`.

### [P3] Консоль: очередь заявок прокручивается вбок на 320 px и при крупном шрифте; кнопки решения уходят за край
- **Где:**
  - `apps/console/app/globals.css:40-47` — `.segmented { display: inline-flex }` без переноса;
  - `apps/console/app/globals.css:160` — переход таблицы в карточки задан в px (`@media (max-width: 720px)`) и не срабатывает при крупном шрифте;
  - почта в карточке заявки не переносится (`verifications/page.tsx:158`).
- **Доказательство** (файлы в `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r3/`):
  - 320 px, шрифт 100 %: `out/console-queue-w320-f16.json` — `scrollWidth 385 > 320`, «Отклонённые» обрезано (`shots/console-queue-w320-f16.png`);
  - 768 px, шрифт 200 %: `scrollWidth 1026 > 768`. Колонки даты и «Решение» с кнопками «Одобрить/Отклонить» за правым краем (`shots/console-queue-w768-f32.png`);
  - 375 px, шрифт 200 %: `scrollWidth 638`, адрес «teacher@school7.examp…» обрезан (`shots/console-font200-queue.png`).

  Вход и журнал аудита при тех же условиях проходят без прокрутки. Тест M1-42 проверял только веб.
- **Почему это проблема:** WCAG 1.4.10 (Reflow, AA) на 320 px и 1.4.4 при 200 %. Модератор с крупным шрифтом на планшете не видит главного действия экрана, пока не прокрутит вбок.
- **Предлагаемое исправление:**
  - `flex-wrap: wrap` (или сетка) у `.segmented`;
  - точку перехода таблицы задать в `em` (например, `max-width: 45em`), чтобы она масштабировалась вместе со шрифтом;
  - `kz-break-anywhere` для почты;
  - адрес `/verifications` добавить в проверку шрифта 200 % и ширины 320 в `apps/console/test/e2e`.

### [P3] Ошибка сервера или сети показывается как ошибка поля: верная почта подсвечивается как «недопустимое значение»
- **Где:**
  - `apps/web/app/teacher/login/OtpLogin.tsx:59-64`;
  - `apps/web/app/teacher/classes/[id]/IssueCardsDialog.tsx:73-76`;
  - `apps/console/app/login/StaffLogin.tsx:42`.

  Везде `fieldErrors(e).x ?? describeProblem(e)` попадает в ошибку поля. В `CreateClassDialog.tsx:63-67` и `apply/page.tsx:149-154` сделано правильно: ошибка поля — у поля, остальное — в `InlineAlert` с `role="alert"`.
- **Доказательство:** `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r3/out/r3-errors-extra.json`:
  - при 500 у поля `invalid=true` и текст «На сервере произошла ошибка…»;
  - при обрыве сети — то же с «Нет связи с сервером…».

  Снимок `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r3/shots/err-otp-500.png`: красная рамка вокруг верного адреса `teacher@school7.example`.
- **Почему это проблема:** WCAG 3.3.1 требует называть поле с ошибкой, а здесь поле верное. Читалка скажет «недопустимое значение», а зрячий учитель увидит красную рамку — оба начнут перепечатывать правильный адрес или число, хотя сбой на сервере.
- **Предлагаемое исправление:** взять схему `CreateClassDialog` для всех трёх форм: `fieldErrors` — к полю с `invalid.request()`, всё остальное — в `InlineAlert tone="danger"`. Фокус при этом не уводить с кнопки: живая область объявит ошибку сама.

### [P3] Мелочи
- **Заголовок вкладки ожидания.** Он остаётся «Ждём учителя · Кәрәҙ», когда экран уже говорит «Вход закрыт», «Заявка устарела» или «Учитель не подтвердил заявку». Причина — статичный `metadata` в `apps/web/app/student/wait/layout.tsx:5`; доказательство — `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r3/out/titles.json`, ключ `wait-closed`. Нужен `useDocumentTitle` по состоянию, как на других экранах (M1-15).
- **Ссылка-логотип на «Мой класс» меньше цели режима.** В «Пчёлке» она 121×36 px при норме ≥ 56, в «Бортнике» 113×36 px при норме ≥ 44 (§7). Где: `apps/web/app/student/class/page.tsx:34`, `packages/ui/src/ui.css:1249-1252`. Доказательство — `bee-targets.json` и `adult-targets.json` в `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r3/out/`. Минимум WCAG 2.5.8 (24 px) выполнен, нарушена норма §7. В раунде 2 я это пропустил.
- **«Подожди минуту», даже когда хватит секунды.**
  - После M1-36 сервер при занятых слотах «в работе» отвечает 429 с `Retry-After: 1` (`apps/api/src/infra/rate-limiter.ts:16,112`). BFF этот заголовок передаёт (`packages/session/src/server.ts:98-102`).
  - Но текст всегда «Подожди минуту» (`packages/session/src/problem.ts:45,58,108-109`).
  - Сканер после ошибки выключает камеру, поэтому ребёнок будет ждать минуту зря. Лучше сказать «Подожди немного», а время брать из `Retry-After`.
- **Журнал аудита консоли.** Роли теперь по-русски, но тип объекта (`teacher_verification`, `class`, `session`) и ключи подробностей (`count: 24 · seats: 1-24`, `reason: refresh_reuse`) по-прежнему кодами. Где: `apps/console/app/audit/page.tsx:39-42,163`; снимок — `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r3/shots/console-1280-audit.png`.
- **Перезагрузка при открытом листе оставляет запись листа в истории.** Следующее «Назад» ничего не меняет на экране, тот же адрес (`/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r3/out/r3-sheets.json`, шаги `reloaded with sheet entry` → `back after reload`). Случай редкий: при загрузке страницы можно заменить запись с меткой `kzSheet` через `replaceState`.

### Предложения (вкусовщина, не находки)
- **QR на доске сразу на `/student/code`.** Адрес публичный и без секрета. Путь «камера → ввод кода» сократится на два нажатия («Я ученик» → «У меня нет карточки»), это в духе §12 п. 1. Шаги на доске можно будет упростить.
- **Подпись под QR.** Сейчас она 14 px, а шаги — 28 px (`r3-board.json`). На проекторе подпись «Наведи камеру телефона — откроется сайт» с задних парт не прочитать: стоит сделать её размером с шаги.
- **Переносы при шрифте 200 %.** `overflow-wrap: anywhere` рвёт слова посередине: «Пользовательск | ое соглашение» (`/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-ux/r3/shots/font200-375-terms.png`). Для русского текста лучше `hyphens: auto` с `lang="ru"`, а `anywhere` оставить для почты и адресов.
- **Ранее перенесено в M2 и не требует действий:** двуязычное приветствие, маскот и озвучка «Пчёлки», ширина ячеек кода.
