## Находки

### [P2] Код класса нельзя закрыть, а заявки по нему не ограничены на класс: один ученик за минуту отправляет учителю сотни заявок
- **Где:**
  - `/Users/kitty/Cyber102/Project2/apps/api/src/modules/org/join.service.ts:100-123`: `createRequest` не ограничивает число заявок ни на класс, ни на устройство.
  - `/Users/kitty/Cyber102/Project2/apps/api/src/modules/identity/student-login.service.ts:35,127`: единственный предел для верных заявок — 300 в минуту с IP.
  - `join.service.ts:173-184`: список заявок за сутки отдаётся без пагинации.
  - `/Users/kitty/Cyber102/Project2/apps/web/app/teacher/classes/[id]/JoinRequestsDialog.tsx:30,78`: диалог опрашивает список каждые 3 с и рисует все элементы; кнопки «Отклонить все» нет.
  - `JoinCodeBoard.tsx:112` и `page.tsx:238`: «Закрыть код класса» только закрывает окно. У кода в контракте одна операция — выпуск (`packages/contracts/openapi.yaml:733`), поэтому код действует до 15 минут.
  - ADR 0016:92 утверждает: «Даже угаданный код даёт только заявку, которую учитель видит и отклоняет».
- **Доказательство:** изолированный стек, `probe-flood.mjs`:
  ```
  одноклассник с одного IPv4, 400 заявок за ~секунды    {"202":300,"429":100}
  с адресов одной /64, 1000 заявок                      {"202":1000}
  учитель: GET join-requests (без пагинации)            200 элементов=1300 23 мс, 219710 байт
  учитель: pendingJoinRequestCount                      1300
  ```
- **Почему это проблема:**
  - Код на доске видит весь класс, а фото доски легко уходит в чат. Скрипт с одного адреса создаёт 300 заявок в минуту, за жизнь кода — до 4 500.
  - Ники выбираются из словаря и могут совпадать, поэтому настоящую заявку от поддельной учитель не отличит.
  - Новый код появляется на той же доске, и заливка начинается заново. Погасить код учитель не может.
  - Итог: вход по коду для класса ломается, а одобрить постороннего становится проще. Одобренный посторонний видит школу и класс.
  - Довод ADR «учитель видит и отклоняет» при сотнях заявок не работает.
- **Предлагаемое исправление:**
  - Предел ожидающих заявок на класс (например, 40 или число свободных мест до `MAX_SEATS`) и не больше одной ожидающей заявки на `installId` в классе. Сверх предела — 409 или 429 с понятным кодом.
  - «Закрыть код класса» гасит код на сервере: новая операция в контракте, например `DELETE /classes/{id}/join-code` (`join_code_expires_at = now()`).
  - «Отклонить все» в диалоге и `limit` или курсор у списка заявок.
  - Тесты: 100 заявок по одному коду дают не больше предела; после закрытия кода — 404.

### [P3] Лимиты по IP считаются на полный адрес IPv6: абонент с сетью /64 их обходит
- **Где:**
  - `/Users/kitty/Cyber102/Project2/apps/api/src/infra/rate-limiter.ts:94-95`: ключ лимита — HMAC полного адреса.
  - `/Users/kitty/Cyber102/Project2/packages/session/src/client-ip.ts:148-153`: BFF передаёт полный адрес.
  - ADR 0016:96 называет потолок на IP единственной защитой кода класса от подбора.
- **Доказательство:** `probe-ipv6.mjs`:
  ```
  один адрес IPv6, 300 неверных кодов:             {"404":100,"429":200}
  адреса одной сети 2001:db8:…::/64, 300 неверных: {"404":300}
  QR: адреса одной /64, 60 неверных:               {"401":60}
  ```
- **Почему это проблема:**
  - Сейчас API слушает только IPv4 (`apps/api/src/main.ts:6`), так что риск зависит от L7-балансировщика в проде (docs/08 §1).
  - Если балансировщик примет IPv6, абоненту обычно достаётся /64. Тогда расчёт ADR 0016 §6 («1 500 кодов за жизнь кода с адреса») теряет смысл: скорость подбора кода класса ограничена только пропускной способностью API.
  - У QR остаются лимит на карточку и 128 бит секрета.
- **Предлагаемое исправление:**
  - В `ipKey` для IPv6 брать префикс /64.
  - Тест: адреса одной /64 делят один лимит.
  - Строка об этом в ADR 0016 §6.

### [P3] Один ученик за школьным NAT закрывает вход по QR и по коду класса всей школе
- **Где:**
  - `/Users/kitty/Cyber102/Project2/apps/api/src/infra/rate-limiter.ts:43`: при F ≥ max ответ 429 получает и верная попытка.
  - `student-login.service.ts:22,34`: лимиты 20 неверных QR и 100 неверных кодов в минуту с IP.
  - ADR 0016:137 записывает это как цену критерия приёмки 5, но риск для школы за одним NAT не разбирает.
- **Доказательство:** `probe-nat.mjs`, `probe-nat-cc.mjs`:
  ```
  шалун: 20 неверных QR с адреса школы                  {"401":20}
  ученики с верными карточками №1–3, тот же адрес       429 rate_limited Retry-After=60
  та же карточка с другого адреса                       200
  шалун: 100 неверных кодов класса (разные installId)   {"404":90,"429":10}
  ученик с верным кодом после этого                     429 Retry-After=60
  ```
- **Почему это проблема:**
  - Из интерфейса так не сделать: веб проверяет полезную нагрузку и контрольный символ до отправки (`apps/web/app/student/qr.ts:98`).
  - Но скрипт с поддельными `TT1.…` по открытому формату из репозитория держит вход закрытым весь урок. Для QR хватает одного запроса в 3 с.
  - Учитель не видит, почему никто не может войти.
- **Предлагаемое исправление (на выбор):**
  - Для QR: после исчерпания лимита IP продолжать проверять карточки с существующим `handle` под лимитом на карточку (10 за 10 мин). Подбор 128-битного секрета и так безнадёжен.
  - Либо считать неудачи QR на устройство с потолком на IP, как у кода класса.
  - Минимум: разобрать риск в ADR 0016 §5–6 и писать в аудит или метрики событие «адрес заблокирован за подбор», чтобы поддержка видела причину.

### [P3] Остаточный риск раунда 2 не записан в ADR 0016
- **Где:** `/Users/kitty/Cyber102/Project2/docs/adr/0016-qr-card-and-class-code.md`.
- **Доказательство:** SUMMARY раунда 2 просил: «системная камера телефона может предложить "найти в интернете" текст QR `TT1.…`. Записать в ADR 0016 как известный риск». Поиск `grep -n -i "остаточн\|известный риск\|камера телефона\|искать\|интернете"` по ADR 0016 ничего не находит.
- **Почему это проблема:** риск, о котором договорились, не зафиксирован. Следующий раунд или пилот его не увидит.
- **Предлагаемое исправление:** абзац в «Последствиях» ADR 0016 с объяснением, почему риск принят. Например: секрет попадает в поисковик только если ребёнок сам нажмёт «искать», а карточку можно перевыпустить.
