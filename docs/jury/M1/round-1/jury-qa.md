## Находки

### [P1] ФИО и должность взрослого попадают в лог API при любом сбое SQL-запроса
- **Где:** `apps/api/src/common/problem.filter.ts:42` пишет в лог `exception.stack`. У ошибки Drizzle сообщение имеет вид `Failed query: … params: <значения>`. Шаблоны `apps/api/src/common/redact.ts:28-36` закрывают только e-mail и токены.
- **Доказательство** (изолированная БД `jqa1`, временный триггер на `pii.adult_profiles` с `RAISE EXCEPTION`, после проверки удалён). Отправил `POST /teacher/verification` с `fullName:"Ғәлиева Әлфиә Рәмилевна"`. Ответ — 500, в логе API:
  `1534:params: Ғәлиева Әлфиә Рәмилевна,Учитель башкирского языка,…,01a19ea0-…`
  Без триггера параметры падающих запросов тоже попадают в лог: при остановке Postgres в логе `params: XXCWG7CMWW` (идентификатор карточки) и идентификаторы аккаунтов.
- **Почему это проблема:** нарушено непреложное правило 5 CLAUDE.md («никаких ПДн в логах»). В продакшене сбои БД неизбежны: statement timeout, обрыв соединения, failover. Тест «логи» проходит только по счастливому пути.
- **Предлагаемое исправление:** для ошибок БД писать в лог только SQLSTATE и имя операции, без `params`; либо в `redact()` вырезать хвост `params:` у `DrizzleQueryError`. Нужен тест: ошибка БД при подаче заявки, затем проверка, что ФИО нет в перехваченном выводе.

### [P2] `RedactingLogger.error()` всегда падает: непредвиденные 500 отдают не Problem Details, а при недоступном Valkey повтор refresh-токена не отзывает семейство
- **Где:** `apps/api/src/common/logger.ts:27-28`. Переопределённый `printStackTrace` вызывает `redactString(stack)` при `stack === undefined`. Вызывается из `problem.filter.ts:42` и `sessions.service.ts:163`.
- **Доказательство:**
  - `new RedactingLogger("QA").error("boom")` приводит к `CRASH: Cannot read properties of undefined (reading 'replace')`; с двумя аргументами — то же самое.
  - Postgres остановлен, `POST /auth/qr` → `500 {"statusCode":500,"error":"Internal Server Error","message":"Cannot read properties of undefined (reading 'replace')"}`, `content-type: application/json`. Те же 500 у `GET /me`, `GET /classes/{id}` и `POST /teacher/verification`.
  - Valkey остановлен, повтор старого R0 → такой же 500. После возврата Valkey новый R1 обновляется с ответом `200 ok — family NOT revoked`, а в `audit_log` 0 записей `session.refresh_reuse_detected`: транзакция откатилась.
- **Почему это проблема:** контракт обещает RFC 9457 (`default: Unexpected`), а наружу уходит внутреннее сообщение. Обнаружение повторного использования не срабатывает, хотя ADR 0015 требует при недоступном Valkey отвечать 503.
- **Предлагаемое исправление:** `if (stack) super.printStackTrace(redactString(stack))`. Добавить юнит-тест логгера и интеграционный тест «внутренняя ошибка → Problem 500». Стоп-лист обновлять после фиксации отзыва в БД, а при сбое Valkey отвечать 503.

### [P2] Лимиты частоты обходятся параллельными запросами (проверка и засчитывание не атомарны)
- **Где:** `apps/api/src/modules/identity/student-login.service.ts:52-62` — сначала `assertBelow`, потом `hit`. `apps/api/src/modules/identity/otp.service.ts:82-86` — `hgetall`, затем `hincrby`, затем `del`; после `del` параллельный `hincrby` заводит ключ заново со счётчиком 1.
- **Доказательство** (скрипты `race-qr.mjs`, `race-card.mjs`, `race-otp2.mjs`):
  - 60 параллельных неверных QR с одного свежего IP: `401 card_invalid: 59 / 24 / 51` в трёх прогонах при лимите 20.
  - 40 неверных секретов на одну карточку: `401: 15` при лимите 10.
  - 60 параллельных неверных кодов на один вызов OTP: `otp_invalid: 8 / 5 / 8 / 12` при лимите 5.
- **Почему это проблема:** критерий 5 и ADR 0016 §5 выполняются только при последовательных запросах. ADR 0015 прямо обещает: «параллельный перебор не обходит лимит в 5 попыток».
- **Предлагаемое исправление:** засчитывать попытку атомарно до проверки (один Lua-скрипт: `INCR` и сравнение с max). Для OTP — `HINCRBY` только при существующем ключе (Lua с `EXISTS`). Добавить тест на параллельную пачку.

### [P2] `Idempotency-Key` не защищает от одновременного повтора: два запроса с одним ключом выпускают 48 мест вместо 24
- **Где:** `apps/api/src/infra/idempotency.ts:18-21` — `get`, затем `fn()`, затем `set NX`; заявки на ключ нет.
- **Доказательство** (`idem.mjs`): два параллельных `POST /classes/{id}/seats {count:24}` с одним ключом дают `['201 seats=1..24', '201 seats=25..48']`, итог `seats in class now: 48`. Тот же ключ с другим телом (1, затем 5) возвращает первый результат без ошибки.
- **Почему это проблема:** ключ нужен как раз для повтора после таймаута, пока первый запрос ещё выполняется. Это важно для будущих мобильных клиентов. API для удаления мест нет, а лимит класса — 99 мест.
- **Предлагаемое исправление:** перед `fn()` ставить `SET NX` с маркером «в работе»; второму запросу отвечать 409 или ждать результата. Сохранять хеш тела и при расхождении отвечать 422.

### [P2] У 91 школы (филиалы, 5 % справочника) название «-»: оно видно при выборе школы, в кабинете, на карточках и в бланке согласия
- **Где:** `apps/api/src/modules/org/directory-import.ts:139` — `csvText(r["short_name_ru"]) ?? name_ru`: прочерк не считается пустым значением.
- **Доказательство:**
  - Запрос к БД `count(*) filter (where short_name_ru='-')` вернул `91|0|1694`.
  - Скриншот `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-qa/pw/H-branch-school-dash.png`: шаг «Выберите школу», поиск «Кумьязы», в списке пункт «-».
  - `cards-pdf.ts:47,80` печатает `Кәрәҙ · ${schoolName}` и `Школа: ${schoolName}`.
- **Почему это проблема:** сельские филиалы — основная аудитория башкирского языка. Учитель и родители видят «-» вместо школы, читалка экрана произносит «Школа -».
- **Предлагаемое исправление:** при импорте считать «-», «—» и пустую строку отсутствием значения и брать `name_ru`. Добавить тест импорта.

### [P2] Таймер кода класса и срок PDF считаются по часам устройства: при часах учителя +20 мин свежий код сразу «истёк»
- **Где:** `apps/web/app/teacher/classes/[id]/JoinCodeBoard.tsx:49-50` (`Date.parse(expiresAt) - Date.now()`), `page.tsx:114` (`jobLive`).
- **Доказательство** (`browser5.mjs`, `page.clock.install(now + 20 мин)`): у только что выпущенного кода показано «DP4-XZT · Код истёк — покажите новый». Скриншот: `/var/folders/2k/bb77553s009dc_yq6n_m7pkc0000gn/T/jury-qa/pw/K-joincode-clock-skew.png`. «Показать новый код» выпускает код, который тоже сразу «истёк».
- **Почему это проблема:** на школьных компьютерах часто неверные часы. Вход по коду класса на таком устройстве не работает: учитель не может показать код.
- **Предлагаемое исправление:** считать срок от момента получения ответа (`expiresInSeconds` или поправка по заголовку `Date`) и не доверять абсолютным часам клиента.

### [P2] Перевыпуск карточки не завершает уже открытые сессии этого места
- **Где:** `apps/api/src/modules/org/classes.service.ts` (`reissue`, около строки 234) отзывает только `seat_cards`. Диалог обещает: «Старая карточка … сразу перестанет работать».
- **Доказательство** (`consent.mjs`): ученик вошёл по карточке №09, учитель перевыпустил её, после чего `seat9 session after reissue: 200 still logged in`. Новый вход по старой карточке получает 403 `card_revoked`.
- **Почему это проблема:** обычно карточку перевыпускают, когда её потеряли. Тот, кто успел войти по чужой карточке, сохраняет доступ к аккаунту ребёнка до 30 дней, а с обновлениями до 90. Отзыв согласия сессии завершает, перевыпуск — нет.
- **Предлагаемое исправление:** при перевыпуске вызывать `revokeAccount(accountId, "card_reissued")` или дать учителю выбор. Добавить тест.

### [P3] Мелочи
1. **Один код OTP даёт две сессии.** Двойное нажатие с верным кодом возвращает `['200 …', '200 …']`: код не строго одноразовый (`otp.service.ts:106`, `del` выполняется после выдачи).
2. **Потерянный ответ на refresh приводит к выходу.** Повтор после потерянного ответа даёт `200 -> 401 refresh_reused` и ложную тревогу в аудите. Отказ от льготного окна осознанный (ADR 0015), но на школьном Wi-Fi это будет случаться.
3. **Английский текст ошибки в интерфейсе.** `/teacher/classes/not-a-uuid` показывает «Что-то сломалось · Проверьте поле: must match format "uuid"», хотя ожидается «Класс не найден»: так страница ведёт себя для несуществующего UUID.
4. **Неверная подсказка в `e2e/run.mjs:8`.** Форма `pnpm e2e -- --repeat-each=3` молча запускает «Running 2 tests» вместо 6. Рабочая форма из `docs/demo/M1.md` — `pnpm e2e --repeat-each=3`.
5. **Названия классов с башкирскими буквами без `lang="ba"`.** На `/teacher` они размечены `lang="ru"`: `["[ru] 7 «Ә»","[ru] 7 «Ғ»",…]`.
6. **Поиск школы зависит от пробела после «№».** Запрос «школа №1» не находит «СОШ № 1»: сначала идут филиалы, у которых в полном имени есть «№1».
7. **ФИО принимает эмодзи и латиницу** (`"😀😀 😀"` → 201). На «Нет доступа» текст предлагает «попросите его добавить вас в класс», но совместного ведения класса нет.
