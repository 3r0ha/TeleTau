# План вехи M1 — Доступ и организации

Источник объёма: `docs/09-roadmap.md` §2 M1. Жюри гейта: `jury-security`, `jury-architecture`, `jury-ux`, `jury-qa`; порог — средняя ≥ 7,5 (M0–M2). Основа: модель данных `docs/07-data-and-api.md` §1.1–2, безопасность `docs/08-infra-security-compliance.md` §5–6, ADR 0009 (псевдонимные детские аккаунты), модули `docs/06-architecture.md` §3, дизайн — утверждённый прототип v2 (`docs/05-design-system.md` §0).

## Что получится

**Учитель:**
1. Входит по e-mail и одноразовому коду (в демо-режиме код всегда 0000).
2. Подаёт заявку на подтверждение: школа из справочника, ФИО, должность.
3. После одобрения модератором в консоли создаёт класс и выпускает QR-карточки.
4. Печатает PDF: карточки и бланк согласия для родителей.

**Ученик:** сканирует QR-карточку, выбирает ник из словаря и попадает в свой класс. Он не вводит ни одного персонального данного. Учитель видит его в списке класса как «№07 · Смелая пчела». Связь номера карточки с ребёнком знает только учитель: он подписывает карточку от руки (ADR 0009).

## Решения владельца
- **Почтовый сервис не разворачиваем.** Вход взрослых — e-mail и одноразовый код, в демо-режиме код фиксированный: **0000**. Включается переменной `AUTH_DEMO_OTP=0000`. Ограничение попыток действует и здесь. Если демо-режим выключен, а провайдера почты нет, `POST /auth/otp/request` отвечает 503.
- **OAuth (Яндекс ID, Сбер ID) в M1 не делаем.** С демо-кодом он не нужен, ключи провайдеров тоже.
- **Справочник районов и школ РБ** собираем сами из открытых источников: `apps/api/data/rb-districts.csv` и `rb-schools.csv`; источники и методика — в `rb-directory.README.md`. Демо-школы для тестов помечаются `is_demo`.

## Решения, которые фиксируем (новые ADR)

| ADR | Решение |
|---|---|
| 0015 | **Токены.** Access-токен — JWT ES256 (`jose`) на 15 мин, в нём `sub`, `kind`, `roles`, `sid`, `did`. Refresh-токен — непрозрачный, 256 бит; в базе хранится только SHA-256. Он ротируется при каждом обновлении, принадлежит «семейству» сессии и привязан к устройству. Повторное предъявление старого refresh-токена отзывает всё семейство и пишет событие в аудит. |
| 0016 | **QR-карточка.** Секрет — 128 бит, кодировка base32 Crockford. В QR лежит ссылка `…/q#TT1.<seat>.<secret>.<check>`: фрагмент после `#` не попадает в логи сервера. Контрольная сумма ловит опечатки. В базе — только хеш секрета. Карточку можно отозвать и перевыпустить. Формат описан тест-векторами (`contracts/test-vectors/qr-card/`), порты Swift и Kotlin — в M6 и M7. **Код класса** — 6 символов, живёт 15 минут; вход по нему требует одобрения учителя на экране. |
| 0017 | **Авторизация и аудит.** RBAC: `student`, `teacher` (`pending` / `verified`), `moderator`, `admin`. ABAC — политики в сервисах модулей: «учитель класса», «участник класса». У каждого эндпоинта есть строка в матрице авторизации; тест падает, если операция из `openapi.yaml` в матрицу не попала. `audit_log` — только вставка: роль БД без `UPDATE`/`DELETE` плюс триггер. |
| 0018 | **PDF на сервере.** `pdfkit` + `qrcode` + встроенный шрифт с полным башкирским алфавитом (OFL, хранится в репозитории). Без ПДн: на карточке номер места, класс, QR и пустая строка «Имя — пишет учитель». |

## Задачи

### Фаза 1 — фундамент вехи (последовательно, один исполнитель)

**T1. Контракт `packages/contracts/openapi.yaml`.**
Добавить эндпоинты M1:
- **Auth:** `POST /auth/qr`, `POST /auth/class-code` (заявка на вход), `GET /auth/class-code/{requestId}` (статус), `POST /auth/otp/request`, `POST /auth/otp/verify`, `POST /auth/refresh`, `POST /auth/logout`.
- **Me:** `GET /me`, `PATCH /me` (ник из словаря, режим UI), `GET /nicknames/suggest`.
- **Org:** `GET /districts`, `GET /schools?district=&q=`, `POST /classes`, `GET /classes`, `GET /classes/{id}`, `POST /classes/{id}/seats` (выпуск N карточек), `GET /classes/{id}/cards.pdf`, `POST /classes/{id}/seats/{seat}/reissue`, `POST /classes/{id}/join-code`, `GET /classes/{id}/join-requests`, `POST /classes/{id}/join-requests/{rid}/{approve|reject}`.
- **Teacher:** `POST /teacher/verification`, `GET /teacher/verification`.
- **Moderation:** `GET /moderation/teacher-verifications`, `POST /moderation/teacher-verifications/{id}/{approve|reject}`.
- **Consent:** `GET /legal-documents/current`, `POST /consents`, `POST /classes/{id}/seats/{seat}/paper-consent`, `POST /consents/{id}/revoke`.
- **Admin:** `GET /admin/audit-log`.

У всех ошибок — Problem Details. Схема безопасности — `bearerAuth`. Сгенерировать типы.
- **Готово, когда** `pnpm contracts:check` зелёный и ломающих изменений нет.

**T2. Тест-векторы и пакет `packages/auth-codes`** (TS).
- Формат QR-полезной нагрузки и кода класса: генерация, разбор, контрольная сумма, нормализация ручного ввода (регистр, похожие символы `O/0`, `I/1`).
- Векторы: валидные и битые полезные нагрузки, опечатки, лишние пробелы, чужой префикс.
- **Готово, когда** векторы проходят в vitest, а `README.md` векторов описывает формат для будущих портов Swift и Kotlin.

**T3. Схемы БД и миграция** (Drizzle, по модулям, ADR 0014):

| Модуль | Таблицы |
|---|---|
| `identity` | `accounts`, `credentials`, `sessions` (с `family_id`), `devices`; в схеме `pii` — `pii.adult_profiles` (e-mail, ФИО — только для взрослых) |
| `org` | `districts`, `schools`, `classes`, `class_seats` (номер места ↔ аккаунт, статус карточки), `memberships`, `join_requests` |
| `consent` | `legal_documents`, `consents` |
| `moderation` | `teacher_verifications` |
| `admin` | `audit_log` (только вставка) |

- **Готово, когда** миграция аддитивна, применяется на чистую базу и проходит `pnpm db:migrate`, а проверка границ зелёная.

**T4. Зависимости и ADR 0015–0018.**
- Поставить в проект все пакеты вехи, чтобы параллельные исполнители не трогали `pnpm-lock.yaml`:
  - API: `jose`, `pdfkit`, `qrcode`, `otplib` (TOTP для сотрудников);
  - веб: `@phosphor-icons/react`, `@playwright/test`, `@axe-core/playwright`;
  - сканер QR в браузере: `BarcodeDetector` с запасным вариантом на `jsqr`.
- Шрифты Golos Text и Nunito (OFL) — локально, с полным `cyrillic-ext`. Это закрывает часть M0-P01: тест на наличие `locl BSH`.

### Фаза 2 — параллельно (два исполнителя, без общих файлов)

**T5. API: модули `identity`, `consent`, `org`, `moderation`, `admin`.**
- **Вход:**
  - QR — ограничение частоты по IP и по месту в классе (Valkey); вход только для живой карточки;
  - код класса — заявка, одобрение учителем, выпуск места;
  - e-mail + одноразовый код: в демо-режиме — фиксированный 0000, 5 попыток; почтового провайдера нет.
- **Сессии:** ротация refresh-токенов и обнаружение повторного использования.
- **Ники:** словарь «прилагательное + существительное» на русском, без башкирского до проверки носителем.
- **Org:**
  - импорт реального справочника из `apps/api/data/rb-districts.csv` и `rb-schools.csv` (`pnpm --filter @teletau/api org:import`; `pnpm dev` загружает его сам); для тестов — демо-школы с `is_demo`;
  - классы, выпуск мест, перевыпуск карточки, PDF.
- **Модерация:** очередь заявок учителей, одобрение и отказ.
- **Согласия:** версии документов; принятие условий взрослым при регистрации; бумажное согласие на место ученика отмечает учитель; отзыв согласия блокирует вход по карточке.
- **Аудит:** выпуск и перевыпуск карточек, решения модератора, изменения согласий, повторное использование refresh-токена, вход сотрудника.
- **Готово, когда** выполнены все пункты:
  - юнит-тесты и интеграционные тесты зелёные;
  - у каждой операции контракта есть строка в **матрице авторизации** (аноним → 401, чужая роль → 403, чужой ресурс → 403 или 404);
  - есть тест: повторное использование refresh-токена отзывает сессию;
  - есть тест: в `pii` нет строк для детских аккаунтов;
  - есть тест: в логах нет e-mail и секретов.

**T6. Дизайн-токены v2 и клиенты.**
- **Токены:** `packages/design-tokens` переходит на палитру прототипа v2:
  - мёд `#FFB703`, глубокий мёд `#E39400`, шоколадный текст `#3B2716`, крем;
  - зелень, вода, коралл, фиолетовый;
  - цвета «губы» кнопок, зоны мест, радиусы по ролям.

  Тёмная тема сохраняется. Тест контраста остаётся зелёным. Снапшоты iOS и Android перезаписываются осознанно, с просмотром картинок.
- **Компоненты** (`packages/ui` или `apps/web/src/ui`): кнопка с «губой», чип, карточка, поле ввода, ввод кода, шестиугольный аватар, прогресс-бар, лист/диалог, тост, верхняя и нижняя панели. Иконки — Phosphor. Все цвета — только из токенов.
- **Экраны веба:**
  - старт («Я ученик» / «Я учитель или взрослый»);
  - ученик: сканер QR (камера или фото), вход по коду класса с ожиданием одобрения, выбор ника, «Ты в классе 5 «Б»»;
  - учитель: e-mail → код → профиль → заявка (выбор района и школы) → ожидание → кабинет → создать класс → страница класса (места, выпуск карточек, PDF, код класса на экран, заявки на вход, ученики появляются без перезагрузки — опрос раз в 3 с);
  - пустые состояния, состояния загрузки, ошибок и офлайна — по прототипу.
- **Консоль:** вход сотрудника (одноразовый код + TOTP), очередь заявок учителей, журнал аудита.
- **Готово, когда** `pnpm lint`, `typecheck` и `build` зелёные, экраны работают против настоящего API, а axe не находит серьёзных нарушений.

### Фаза 3 — сборка и проверка

**T7. Сквозные тесты (Playwright)** по сценарию демо `docs/demo/M1.md`:
- учитель → модератор → класс → PDF;
- QR из PDF декодируется → ученик входит и выбирает ник меньше чем за 30 с;
- учитель видит ученика;
- вход в чужой класс → 403.

Запуск: `pnpm e2e` — в `verify.sh` и CI. Браузер берётся из уже скачанного кеша Playwright, ничего не ставится глобально.

**T8. Документы:** `docs/06` (модули и аудит), `docs/07` (фактические таблицы и эндпоинты), `CLAUDE.md` (новые команды), демо.

## Критерии приёмки вехи

1. Учитель проходит путь от e-mail до класса. Выпуск 24 карточек даёт PDF: 3 страницы карточек плюс бланк согласия. Каждый QR из PDF декодируется в полезную нагрузку, которая проходит векторы.
2. Ученик входит по QR и выбирает ник **меньше чем за 30 с** (замер в e2e). Ни на одном шаге у ребёнка не спрашивают ПДн; для детских аккаунтов в схеме `pii` нет строк (тест).
3. Учитель видит нового ученика не позже чем через 5 с без перезагрузки страницы.
4. **Матрица авторизации:** у каждой операции M1 есть тест «аноним / чужая роль / чужой ресурс». Попытка учителя открыть чужой класс → 403; ученика — чужой класс → 403.
5. Повторное использование refresh-токена отзывает всё семейство сессии. 20 неверных попыток QR с одного IP за минуту дают 429.
6. В `audit_log` есть записи о выпуске и перевыпуске карточек, о решениях модератора, об изменениях согласий и о повторном использовании refresh-токена. `UPDATE` и `DELETE` на `audit_log` запрещены на уровне БД (тест).
7. В логах API нет e-mail, секретов карточек и токенов (тест на перехват логов).
8. Веб: токены v2 и компоненты; контраст AA (тест); axe без серьёзных нарушений на экранах онбординга; работает клавиатура и читалка экрана; башкирский текст размечен `lang="ba"`.
9. `scripts/verify.sh` зелёный на Node 24, включая e2e и мобильные снапшоты на новых токенах.

## Риски и вопросы владельцу (не блокируют)
- Справочник собран из открытых источников. Его полнота и актуальность зависят от источника; пробелы описаны в `rb-directory.README.md`.
- **Фиксированный код 0000 — осознанное решение для хакатона.** Жюри безопасности должно оценивать его как демо-режим, а не как дефект; в проде его заменит почтовый провайдер.
- **Камера в браузере на школьных устройствах:** есть запасной вариант — фото карточки или код класса.
- Тексты интерфейса — черновик разработчика, их вычитает редактор (правило §0 п. 6 дизайна). Новый башкирский текст — только с пометкой `needs_native_review`.

## Уточнения по итогам фазы 1
- **Секрет карточки — 130 бит** (26 символов base32 без «хвоста»). Контрольная сумма — 2 символа по модулю 1021. В QR вместо номера места лежит публичный 10-символьный идентификатор карточки: номер места не уникален глобально, а по идентификатору удобно ограничивать частоту попыток. Формат — `contracts/test-vectors/qr-card/README.md`, ADR 0016.
- **Таблица `seat_cards`** хранит историю выпуска карточек. Вход старой карточкой после перевыпуска отвечает `card_revoked`. У места без карточки статус `none`.
- **PDF через задание печати.** В базе лежат только хеши секретов. Сами секреты лежат в Valkey в зашифрованном виде 30 минут, и `GET /classes/{id}/cards.pdf?printJob=` рендерит PDF из них. После истечения срока ответ — 410, карточки нужно перевыпустить.
- **Защиты в базе:** триггеры запрещают `UPDATE`, `DELETE` и `TRUNCATE` в `audit_log` и не дают завести строку `pii.adult_profiles` для детского аккаунта. Отдельная роль `teletau_app`; перевод dev на неё отложен до M4 (ADR 0017).
- **У каждой операции контракта есть правило доступа `x-access`.** `check.mjs` проверяет, что правило есть и что объявлены ответы 401, 403, 404 и 422.
- **Шрифты локальные** (`packages/design-tokens/fonts/`). Все 18 башкирских букв есть. У Nunito есть `locl BSH`, у Golos Text нет. В обоих шрифтах Ҫ и Ҙ без седили, то есть башкирской формой; см. M0-P01.
- **Новые переменные окружения:** `AUTH_DEMO_OTP`, `AUTH_JWT_PRIVATE_KEY`, `AUTH_SECRET_PEPPER`, `AUTH_ENCRYPTION_KEY`, `PUBLIC_WEB_URL`, `PUBLIC_CONSOLE_URL`, `NEXT_PUBLIC_API_URL`.

## Ретро

**Итог.** Веха закрыта решением владельца после раунда 3 (вариант «доработка без раунда 4», `docs/jury/M1/round-3/SUMMARY.md`). Оценки раунда 3: security 8,6, architecture 8,6, ux 8,5, qa 6,8. У QA оценка снижена из‑за мигающего e2e, это исправлено в M1-50. Все P0/P1 трёх раундов закрыты. P2/P3, которые не исправлены, перенесены в `docs/backlog.md` с целевыми вехами.

**Что замедлило.**
- Три раунда по четыре жюри, каждый по несколько часов. Большинство находок раундов 2–3 — шлифовка крайних случаев (NAT, IPv6, гонки, тексты) для продукта, которого пользователи ещё не видели. По решению владельца до показа работаем в режиме «сначала продукт», без жюри (`docs/STATUS.md`, `docs/plans/M2.md`).
- Исправления сами порождали новые находки:
  - повторная выдача сессии (M1-07) открыла обход отзыва согласия (M1-35);
  - атомарный резерв лимита (M1-05) стал блокировать школу за NAT (M1-36).

  Урок: у правки пути входа нужен тест «все решения учителя закрывают и этот путь».
- Тесты зависели от состояния общей dev-БД: интеграционные тесты засоряли очередь модератора, и e2e мигал.
- Моки API разошлись с настоящим API: мок разрешал `DELETE` в CORS, настоящий API — нет.

**Что превращено в автоматические проверки.**
- Интеграционные тесты работают в отдельной базе `teletau_it` и Valkey `/1` (M1-50). Тест проверяет, что база — именно `_it`.
- Методы CORS выводятся из контракта (`corsMethods()`). Тест «preflight пропускает каждый метод контракта» — `apps/api/test/contract-routes.test.ts`.
- Матрица управляющих символов по всем операциям контракта (M1-40). Матрица авторизации требует строку для каждой новой операции.
- Тест «двойной щелчок по «Показать ещё» не даёт дублей» на моках консоли и веба. Помощник e2e листает очередь любой длины.
- Тест «план `JoinGrants.close` использует индекс» (EXPLAIN).
