# 08. Инфраструктура, безопасность и каналы

> Факты о каналах и магазинах — из `docs/research/03-legal-infra-distribution.md`. Юридические вопросы вне скоупа хакатона (§7).

## 1. Хостинг и окружения

| Окружение | Назначение | Где | Данные |
|---|---|---|---|
| `local` | Разработка | docker-compose у разработчика | Синтетические |
| `ci` | Тесты, сборки | Раннеры CI (Linux + macOS для iOS) | Синтетические |
| `dev` | Интеграция веток | Облако РФ, отдельный проект | Синтетические |
| `stage` | Приёмка вех, демо жюри и заказчику, нагрузочные тесты | Облако РФ, копия прода по топологии (меньше узлов) | Синтетические + обезличенные копии |
| `prod` | Эксплуатация | Облако РФ (Yandex Cloud) | Реальные |

Базовый провайдер — **Yandex Cloud**: зрелые managed-сервисы, три зоны доступности, резервный AI-провайдер внутри облака. Cloud.ru и VK Cloud дешевле на 12–18%. Переносимость обеспечивают Kubernetes + Terraform + открытые форматы бэкапов.

### Топология prod (базовый сценарий — 100 тыс. MAU)

```
Интернет → DNS → CDN (статика, медиа, офлайн-пакеты) ──────────────────────────┐
         → WAF + Anti-DDoS (веб-фронт и эндпоинты авторизации) → L7-балансировщик │
                                                                   │              │
             Managed Kubernetes (региональный мастер, 3 зоны, 6 узлов 4/16, автоскейл)
             ├── api (HPA по CPU и RPS)          ├── realtime (WebSocket, sticky-сессии)
             ├── web / console (SSR)             ├── bot-gateway
             ├── ai-gateway                      ├── workers (BullMQ)
             └── ml-worker (CronJob + по событию)
                     │
   Managed PostgreSQL 17 (3 хоста 4/16, 3 зоны, синхронная реплика, PITR)
   Managed Valkey (2 × 2/8)          Managed ClickHouse (1 × 4/16)
   Object Storage (медиа, пакеты, релизы, бэкапы — отдельный бакет с блокировкой удаления)
   Lockbox / KMS (секреты, ключи шифрования)
```

Расчёт стоимости по профилям 10/100/300 тыс. MAU — `12-finance.md` §3 и исследование, раздел 2.4.

## 2. CI/CD

- **CI на каждый пул-реквест:** линтеры и типы, модульные и контрактные тесты, тест-векторы на TS/Swift/Kotlin, проверка контракта (`oasdiff`), сборки iOS и Android, SAST (Semgrep), секрет-сканер (gitleaks), аудит зависимостей (`pnpm audit`, OWASP dependency-check), SBOM (CycloneDX), проверка границ модулей, проверка контраста дизайн-токенов.
- **CD:** GitOps (Argo CD). `main` → автодеплой на `dev`; релизный тег → `stage`; ручное подтверждение → `prod` с канареечным выкатом (10% → 50% → 100%) и автоматическим откатом по SLO.
- **Миграции БД:** только обратно совместимые (expand → migrate → contract), применяются отдельной задачей до выката кода.
- **Мобильные:** fastlane — сборка, подпись, загрузка в TestFlight и тестовые треки магазинов; номер сборки из CI; принудительное обновление через удалённую конфигурацию.
- **Контент:** релиз контента (курс, офлайн-пакеты) отделён от релиза кода и проходит ревью методиста в консоли.

## 3. Наблюдаемость и SLO

| SLO | Цель | Окно |
|---|---|---|
| Доступность API в учебное время (пн–сб 07:00–16:00 по Уфе) | 99,5% | 28 дней |
| p95 задержки учебных эндпоинтов | < 200 мс | 28 дней |
| Успешная синхронизация офлайн-событий | 99,9% событий без потерь | 28 дней |
| Задержка событий урок-битвы | p95 < 300 мс | на сессию |
| Доставка напоминаний вне тихих часов | 99% | 7 дней |

Стек: OpenTelemetry (трейсы от клиента до БД), VictoriaMetrics + Grafana, Loki, Tempo, self-hosted Sentry для серверных и клиентских ошибок. Алерты — по сжиганию бюджета ошибок, а не по отдельным порогам. Бизнес-дашборды (North Star, удержание, корпус) — в ClickHouse + Grafana/Superset. В логах, трейсах и ошибках нет ПДн: фильтры на уровне SDK и коллектора, проверка жюри безопасности.

## 4. Резервное копирование и восстановление

- PostgreSQL: PITR (непрерывное архивирование WAL) + ежедневные снапшоты; хранение 30 дней; копия в отдельном бакете с блокировкой удаления (защита от шифровальщиков и ошибок оператора).
- Object Storage: версионирование, межзонная репликация.
- ClickHouse: ежедневные бэкапы агрегатов; сырые события допускается восстанавливать из потока.
- **RPO ≤ 15 мин, RTO ≤ 4 ч.** Учения по восстановлению — на M11 и далее раз в квартал, с протоколом.
- Журнал голосов (`judgments`) дополнительно экспортируется ежедневно в неизменяемый архив — это ценнейший актив корпуса.

## 5. Меры безопасности

### Приложение (OWASP ASVS уровня 2)
- Аутентификация: QR-карточки и коды классов с высокой энтропией, ограничение попыток, отзыв; взрослые — OAuth-провайдеры РФ; внутренние роли консоли — обязательная 2FA; админы — дополнительно IP-ограничения.
- Сессии: access-токен 15 мин, ротируемый refresh-токен с привязкой к устройству и обнаружением повторного использования.
- Авторизация: RBAC + ABAC (политики на уровне сервиса). **Тест «чужой ресурс → 403/404» для каждого эндпоинта.**
- Ввод и вывод: схемы на границе, параметризованные запросы, экранирование UGC, CSP без `unsafe-inline`, защита от CSV-инъекций в выгрузках, ограничения на загрузку файлов.
- Ограничение частоты запросов: по IP, по аккаунту, по устройству; отдельные лимиты для AI и голосований.
- Аудит-лог действий внутренних ролей (только вставка).

### Мобильные (OWASP MASVS L1)
Токены — в Keychain / Android Keystore; без чувствительных данных в бэкапах и на снимке переключателя приложений (экраны родителя и учителя); ATS и Network Security Config без глобальных исключений; релизные сборки без отладочных флагов; обфускация (R8); проверка целостности контента (подписанные офлайн-пакеты).

### Инфраструктура
Секреты — в Lockbox/KMS, не в репозитории и не в образах; шифрование дисков и бакетов; сетевые политики Kubernetes (запрет по умолчанию); доступ к проду — через бастион с аудитом; сканирование образов; обновления по SLA: критические уязвимости — 24 ч, высокие — 7 дней.

### Процессы
Жюри безопасности на каждой вехе (`10-jury-loop.md`), внешний пентест перед запуском и ежегодно, bug bounty (опционально, с 2-го года), план реагирования на инциденты, обучение команды и модераторов.

## 6. Модель угроз (кратко)

| Угроза | Актив | Меры |
|---|---|---|
| Доступ к данным чужого класса или ребёнка (IDOR) | ПДн, прогресс | ABAC, тесты авторизации, жюри безопасности |
| Подбор QR-кодов и кодов классов | Аккаунты детей | Энтропия ≥ 80 бит у QR, короткие коды классов живут недолго и требуют подтверждения учителя, ограничение попыток |
| Накрутка баллов модифицированным клиентом | Честность рейтингов | Сервер пересчитывает баллы из событий, проверяет ответы с известным ключом |
| Сговор и отравление корпуса | Качество базы | Consensus Engine: веса, контрольные задания, кворум из разных школ, антифрод |
| Инъекции промптов | AI-слой | Изоляция блоков, JSON-схемы, валидаторы, отсутствие инструментов с побочными эффектами |
| Утечка ПДн через логи, аналитику или AI | ПДн | Фильтры, псевдонимизация в ClickHouse, ПДн не уходят в промпты |
| Компрометация учётной записи сотрудника | Всё | 2FA, минимальные права, аудит, IP-ограничения |
| DDoS в учебное время | Доступность | CDN, WAF/Anti-DDoS, автоскейл, деградация второстепенного |
| Компрометация цепочки поставок | Код | Lock-файлы, SBOM, сканирование, подпись артефактов |
| Вредоносный или противоправный UGC | Репутация, закон | Премодерация, словари, классификатор, жалобы, нет свободного общения детей |

## 7. Правовые вопросы — вне скоупа хакатона

**Решение владельца:** проект делается по ТЗ хакатона. Юридические вопросы — статус информационной системы, оператор ПДн, согласия, аттестация, ограничения мессенджеров для госсектора — на продукт не влияют. Исследование `research/03-legal-infra-distribution.md` сохранено как справка на случай промышленного внедрения после хакатона.

Инженерные принципы, которые мы **сохраняем** — не как юридические требования, а как качество продукта и аргумент для жюри:
- **минимум данных о детях:** вход по QR-карточке или коду класса, ник из генератора; без ФИО, телефона, e-mail, фото, геолокации и анкетных вопросов о национальности; голос не храним — говорение обрабатывается «на лету»;
- **никаких персональных данных** в промптах GigaChat, логах, аналитике, push-уведомлениях и сообщениях бота;
- нет свободного чата между детьми; модерация пользовательского контента;
- хостинг в российском облаке; своя аналитика и сбор ошибок без зарубежных SaaS-SDK в приложениях — меньше внешних зависимостей и меньше риск блокировок;
- никакой рекламы;
- доступность WCAG 2.2 AA.

## 8. Каналы и распространение

### Telegram-бот + Telegram Mini App (по ТЗ)
- Мессенджер-канал продукта — **Telegram**: бот для быстрых сценариев и Mini App для полноценных уроков.
- **Технический риск:** с 10.02.2026 Telegram в РФ официально замедляется (`research/03` §3.1). Меры:
  - бот — дополнительный канал, а не единственный вход в продукт;
  - Mini App — та же веб-сборка: если Telegram тормозит, ученик открывает ту же ссылку в браузере без потери прогресса;
  - бот не хранит состояние урока, всё состояние — на сервере;
  - очередь исходящих сообщений с повторами и мониторинг доступности Bot API;
  - напоминания дублируются пушем и e-mail.
- Привязка Telegram-аккаунта — одноразовым кодом из приложения или веба; хранится только технический `chat_id`.

### Каналы доставки (приоритет)
1. **Веб/PWA, offline-first** — работает на любом устройстве без магазинов и переживает отключения мобильного интернета, которые в РБ случаются регулярно (`research/03` §4.4).
2. **Telegram** — бот и Mini App.
3. **Android:** RuStore (предустановлен на новых устройствах), Huawei AppGallery, Xiaomi GetApps, Samsung Galaxy Store; Google Play — по возможности. Заранее закрепить package name в Android Developer Console: с 2027 года действует верификация Android-разработчиков.
4. **iOS App Store.** Apple удаляет часть российских приложений и при удалении отзывает push-токены. Нативное iOS-приложение делаем, а **PWA остаётся запасным путём** для iPhone.

### Push-уведомления
- Android — RuStore Universal Push SDK (RuStore + FCM + HMS с переключением); iOS — APNs.
- В уведомлении нет персональных данных: только «Тебя ждёт фраза дня».
- Резервные каналы: Telegram-бот (если аккаунт привязан), e-mail учителям и родителям, внутри приложения.
- Продукт полностью работает без пушей.

### Вход
- **Дети:** QR-карточка или код класса + PIN.
- **Учителя, родители, взрослые:** e-mail или телефон + одноразовый код, Telegram Login, Сбер ID, Яндекс ID.

### Контент и магазины
Возрастная маркировка 6+ (модули для 1–4 классов — 0+) в магазинах; модерация пользовательского контента (стоп-словари на русском и башкирском, ИИ-фильтр как помощник, жалобы).
