# Гейт жюри

Процесс и правила — `docs/10-jury-loop.md`. Этот навык — пошаговая инструкция для оркестратора (основного агента).

## 1. Подготовка
1. Определи веху: из аргумента (`M3`) или из `docs/STATUS.md` (поле «Текущая веха»).
2. Определи номер раунда: следующий после последней папки `docs/jury/Mx/round-*`. Если раунд > 3 — не запускай жюри, а перейди к §6 «Эскалация человеку».
3. Определи состав жюри по матрице `docs/10-jury-loop.md` §3 (или из аргумента).
4. Убедись, что самопроверка зелёная (линтеры, типы, тесты, тест-векторы, сборки — команды в `CLAUDE.md`). Если красная — **не запускай жюри**, сначала чини: жюри не должны тратить время на то, что ловит CI.
5. Для раунда 2+ собери прошлые находки каждого жюри из `docs/jury/Mx/round-(N-1)/jury-*.md`.

## 2. Запуск жюри
Запусти всех жюри **одним сообщением, параллельно** (инструмент Agent, `subagent_type` = имя агента, например `jury-ux`). Каждому передай короткий бриф:

```
Веха: Mx «<название>». Раунд: N. Порог вехи: <8.0 или 7.5 для M0–M2>.
Объём и критерии приёмки: docs/09-roadmap.md (раздел Mx) и docs/plans/Mx.md.
Демо: docs/demo/Mx.md (если есть).
[Раунд 2+] Твои прошлые находки: <вставить список ID и заголовков из прошлого отчёта>.
Проверь независимо по своей инструкции и верни отчёт в формате docs/10-jury-loop.md §7.
```

Не передавай жюри свою оценку работы, список «что я сделал хорошо» или предположения о результатах — только веху, критерии и прошлые находки.

## 3. Сохранение отчётов
Каждый вернувшийся отчёт сохрани без изменений в `docs/jury/Mx/round-N/<имя-жюри>.md`.

## 4. Триаж
1. Собери все находки в одну таблицу: ID (`<жюри>-<номер>`), серьёзность, заголовок, где, доказательство есть/нет.
2. Отбрось находки без доказательства (отметь «отброшено: нет доказательства»).
3. Объедини дубликаты от разных жюри (оставь наибольшую серьёзность, перечисли источники).
4. **Каждую P0 и P1 воспроизведи сам** (запусти команду/тест/шаги). Не воспроизвелось → понизь или отбрось с пояснением.
5. Посчитай средние оценки каждого жюри и проверь условия гейта (`docs/10-jury-loop.md` §5).
6. Запиши `docs/jury/Mx/round-N/SUMMARY.md`:

```markdown
# Гейт Mx · Раунд N
## Решение: ПРОЙДЕН | НЕ ПРОЙДЕН
## Оценки жюри
| Жюри | Средняя | Мин. критерий | Вердикт |
## Условия гейта
- [ ] Нет открытых P0/P1 …
## Находки после триажа
| ID | Серьёзность | Заголовок | Источники | Статус (открыта/отброшена/дубликат) | Воспроизведено |
## План доработки (если не пройден)
1. P0 … 2. P1 … 3. P2 …
## Перенос в backlog (P2/P3 с обоснованием)
```

7. Обнови `docs/STATUS.md` (раунд, решение, ссылка на SUMMARY).

## 5. Если гейт не пройден
Исправь находки в порядке P0 → P1 → P2 (для каждой — тест, который ловит проблему, затем исправление), прогони самопроверку и запусти этот навык снова (следующий раунд). В следующем раунде можно запускать только жюри, у которых был FAIL или открытые находки, плюс QA (регресс) — но на финальном раунде вехи M11 — всех.

## 6. Эскалация человеку
Если после 3-го раунда гейт не пройден — остановись и подготовь владельцу проекта короткую сводку: что не проходит, почему, 2–3 варианта решения (доработать / осознанно снизить порог / перенести в следующую веху) с твоей рекомендацией. Не снижай пороги и не переносишь P0/P1 самостоятельно.

## 7. Если гейт пройден
Отметь веху закрытой в `docs/STATUS.md`, перенеси оставшиеся P2/P3 в `docs/backlog.md`, кратко сообщи пользователю итог: оценки жюри, сколько находок исправлено, что перенесено.
